# 从开局到通关的自动游玩录像

这是一个通过正常输入操作真实游戏的示例录制器，支持汽车、白名单、造门与《网安仙人》四条公开真结局，复用第二版宣传片的本地 HTTP 服务、Chromium 启动配置和 ffmpeg 编码工具。它不加载宣传片的 `shots.js` 或 `v1/trailer.js`，也不使用宣传片的摆镜头、场景切换或状态设置方法。

## 已生成的示例

[三条路线入口](endings.html) · [汽车](playthrough.html) · [白名单](runs/face/index.html) · [造门](runs/portal/index.html)

三条录像均为 960×540、H.264 + AAC，预知梦难度，全新开局，保留原速、完整游戏原声和结局演出。每条观看页都提供成片与 gzip 操作日志下载。

| 路线 | 时长 | 大小 | 随机天赋 | 章节 |
| --- | --- | --- | --- | --- |
| 汽车《闸门》 | 7 分 19.6 秒 | 19.5 MiB | 秒表 | 11 |
| 白名单《白名单》 | 10 分 38.9 秒 | 25.6 MiB | 编程社 | 10 |
| 造门《门》 | 13 分 35.2 秒 | 30.9 MiB | 夜视 | 13 |

三条实录均在第 1 天通关，没有死亡，最终违规为 0，页面错误为 0，导航重规划为 0。调试、无敌、加速移动关闭，搜查读条和过场开启。汽车通过两个出口，最后驾驶采样为 318.3、车辆 3/3，随后正常触发结局；白名单记录了学号写入、数据同步和三题通过；造门记录了日记、二／四／五楼图纸、四件材料实物及完成装配后的真结局。

本例在云端软件渲染环境录制，汽车、白名单、造门的抽样帧间隔中位数分别约 0.233 秒、0.267 秒、0.250 秒，画面流畅度有限。MP4 的 25 FPS 是编码帧率，包含重复画面。需要更流畅的实录时，可在有 GPU 的机器上用下述 `--gpu` 参数重新生成。

白名单和造门录像来自干净提交 `e8c38e4`，汽车重录来自干净提交 `01b41ae`；两者只差一项新增交互测试。各日志中的七个生成器文件哈希已逐一与其提交核对。相关导航、交互、编码、观看页与宣传片兼容回归共 **18 项通过**；观看页和路线入口的桌面与 390 像素手机布局、末尾章节跳转也通过了独立浏览器检查。

旧汽车录像在检查后约 80.9 秒才走出教学楼。新汽车、白名单、造门录像相同阶段分别为 **26.6 秒、24.3 秒、27.3 秒**，均没有卡门重规划。这是各次实际录制的观察值；随机事件不同，不作为固定性能保证。首轮白名单尝试暴露了名单异象抢占楼梯交互的问题，已修复并补充回归；失败尝试未作为通关成片发布。

## 运行

需要 Python 3、Python Playwright、Chromium 和带 libx264 的 ffmpeg / ffprobe。在仓库根目录执行：

```bash
python3 -m pip install playwright
python3 -m playwright install chromium ffmpeg
python3 video/playthrough.py --out video/build/my-playthrough
```

每条路线分别启动一个全新的浏览器存档：

```bash
python3 video/playthrough.py --route car --out video/build/car
python3 video/playthrough.py --route face --out video/build/face
python3 video/playthrough.py --route portal --timeout 1800 --out video/build/portal
python3 video/playthrough.py --route cyber --timeout 4200 --out video/build/cyber
```

默认 `--route car`。造门路线涉及更多探索和随机材料，建议给它 1800 秒上限。《网安仙人》包含联网、充电、解谜与 600 运行秒生存，建议给它 4200 秒上限。上述命令顺序运行，避免软件渲染时多个浏览器争抢 CPU。每个输出目录都是独立的成片、观看页、章节和核验日志。

也可以指定已安装的 Chromium：

```bash
CHROMIUM_EXECUTABLE=/usr/bin/chromium python3 video/playthrough.py --out video/build/my-playthrough
```

每次使用新的或空的输出目录。程序不会覆盖已有录像。`--timeout 1200` 是整次尝试的现实秒数上限；`--quality 0` 使用游戏的流畅画质，可以选择 0–4。软件渲染建议使用默认档位；有 GPU 的机器可加 `--gpu --quality 1`，让浏览器使用默认图形后端，提高录制流畅度。`--no-video` 仅检查路线并保存日志、末帧，适合调试自动操作代码。Playwright 自带的录制用 ffmpeg 和系统中负责最终编码的 ffmpeg 都需要安装。

《先辈》目前在游戏代码中归为隐藏结局，没有 `true` 标记，不纳入公开真结局实录。假结局与死亡不会通过录制成功检查。

这是预先知道路线的自动玩家，不是人类初见实况或盲测。脚本会读取地图、碰撞、当前位置、威胁状态和已获得的调查记录，用来规划路线和决定按键。当前按路线正常选择天赋（《网安仙人》选择科技党）；钥匙掉落、无线耗时、谜题与异象仍由游戏决定，没有固定随机种子，也不承诺每次结果或时长相同。

所有行为都通过正常输入处理：触屏摇杆负责移动与减速，另一根手指拖动视角；按键负责交互、背包、选项与驾驶。桌面浏览器同样使用游戏原有的触屏控件，没有新增绕过碰撞的移动方法。旧版汽车录像使用键鼠，新录像在摘要中标明控制方式。脚本不修改位置、时钟、SAN、背包、存档或危险状态，不调用调试功能和结局函数。死亡、寻路失败、超时或页面报错会让本次录制失败，保留记录，不会自动复活、读档拼接或把失败标成通关。

## 导航与脱困

早期汽车录像在检查后绕门来回移动：软件渲染一帧会积累多个物理步，持续按 W 会越过小路点；仅比较五秒前后的位置，也会把来回摆动误判为前进。现在由独立的 `navigation.js` 计算靠近路点时的摇杆幅度，按实测帧间隔预留刹停距离。

2026-11-03 录制网络路线时补充：路径采样间隔收紧至 0.35 单位，并为身体保留避让余量，避免漏掉储物柜边角的短碰撞段。接近并排双门时先核对实际交互对象，避免按键选中另一扇已开启的门并将它关上。隔离测试覆盖教学楼与实验楼的连廊往返、普通学生机无钥匙连接及旧路线交互。

路点只有在到达后或下一段满足完整身体碰撞检测时才会跳过。进度以剩余折线路程是否刷新最佳值衡量，六秒没有实质进展就停止、重规划；连续三次恢复仍无效则明确失败。威胁处理和界面阻挡期间不累计停滞时间。室外冲刺使用不同的开始、停止体力阈值，避免反复切换。

`tests/test_pilot_navigation.py` 覆盖低帧率和快慢帧交替下的刹停、往返运动检测，以及旧录像具体卡门位置在 0.35 秒物理帧下正常开门出教室；另外验证名单异象不能被误认成楼梯选项，且显微镜、隧道、日记、图纸都能通过正常输入交互。这些浏览器用例明确是隔离测试场景，不作为真实通关录像。完整录像仍从主菜单新建游戏开始。

## 输出与检查

| 文件 | 内容 |
| --- | --- |
| `progress.json` / `live-frame.png` | 长时间录制时的最新状态与诊断截图；不用于拼接成片。 |
| `playthrough.mp4` | 通关成功后生成的完整成片，960×540，H.264 + AAC，原速播放，无剪辑。 |
| `gameplay.webm` | Playwright 直接录下的浏览器画面，包含游戏 HUD、开场和结局。 |
| `game-audio.webm` / `game-audio.mka` | 从游戏 Web Audio 输出旁路录制的实际声音；后者仅重新封装。 |
| `run.json` | 源提交、生成器哈希、画质、路线、按键与触屏输入、路径重规划、选项文字、路线里程碑、每秒状态观察、最终结局、页面报错、成片哈希。 |
| `last-frame.png` | 录制结束时的完整页面截图；失败时用于定位问题。 |
| `index.html` / `playthrough-summary.json` | 带章节跳转的观看页面和轻量摘要。 |
| `playthrough-run.json.gz` / `playthrough-poster.jpg` | 完整操作日志的压缩副本，以及从录像中提取的封面。 |

成功后在仓库根目录运行 `python3 video/capture.py --directory video/build/my-playthrough --port 8000`，打开 `http://localhost:8000/` 观看。这个本地服务支持浏览器按字节读取视频，章节跳转可立即生效。章节时间取整到秒，仅用于导航；没有改变原始录像。

画面角落标明「脚本操作 · 正常规则」和当前阶段，保留游戏原有的 HUD 和提示。原声与浏览器录像分开捕获，编码时按记录末端对齐并记下偏移量；没有用宣传片配乐代替游戏音效。编码只改变格式和压缩率，不加速，也不截去等待、搜查或遇险过程。

WebGL 在无 GPU 环境中可能出现低帧率；录制器不通过关闭游戏主循环、手动推进模拟或提高移速弥补性能。游戏本身的暂停、演出、对话与慢帧处理保持原样。成片是一次成功的示范路径，不代表所有天赋、异象或路线都经过完整验证。

## 代码分工

- `capture.py`：宣传片和游玩录像共用的服务器、Chromium 配置。
- `playthrough.py`：新浏览器档案、正常点击开局、实时录制、结果检查、日志和 MP4 编码。
- `playthrough.js`：输入操作、只读寻路、常见危险处理和汽车驾驶。
- `cyber.js`：《网安仙人》的充电／等待、正常电脑交互及终端文件求解。通过界面输入 `cat` 后读取屏幕文字，不读取生成器答案或调用终端执行函数；坐下与起身处理同化风险，不使用课堂六倍快进；往返均走二楼连廊。
- `game-audio.js`：旁路连接游戏音频输出，不改变原本的扬声器连接。
- `example.py` / `playthrough.html`：核对成片哈希，生成观看页、章节、日志压缩包和封面。
- `render.py` / `shots.js` / `score.py`：第二版宣传片流程继续单独使用；第一版在 `v1/` 存档。

这些文件仅由制作脚本加载，游戏主页不加载自动玩家或录音代码。中间文件保存在已忽略的 `video/build/` 下。
