# 从开局到通关的自动游玩录像

这是一个通过键鼠输入操作真实游戏的示例录制器，复用第二版宣传片的本地 HTTP 服务、Chromium 启动配置和 ffmpeg 编码工具。它不加载宣传片的 `shots.js` 或 `v1/trailer.js`，也不使用宣传片的摆镜头、场景切换或状态设置方法。

## 运行

需要 Python 3、Python Playwright、Chromium 和带 libx264 的 ffmpeg / ffprobe。在仓库根目录执行：

```bash
python3 -m pip install playwright
python3 -m playwright install chromium ffmpeg
python3 video/playthrough.py --out video/build/my-playthrough
```

也可以指定已安装的 Chromium：

```bash
CHROMIUM_EXECUTABLE=/usr/bin/chromium python3 video/playthrough.py --out video/build/my-playthrough
```

每次使用新的或空的输出目录。程序不会覆盖已有录像。`--timeout 1200` 是整次尝试的现实秒数上限；`--quality 0` 使用游戏的流畅画质，可以选择 0–4。软件渲染建议使用默认档位；有 GPU 的机器可加 `--gpu --quality 1`，让浏览器使用默认图形后端，提高录制流畅度。`--no-video` 仅检查路线并保存日志、末帧，适合调试自动操作代码。Playwright 自带的录制用 ffmpeg 和系统中负责最终编码的 ffmpeg 都需要安装。

## 示例路线

新建预知梦难度游戏，阅读开场 → 调查自己的课桌 → 阅读讲台移交单并登记外出 → 留在教室接受第一次集合检查 → 步行到行政楼，经楼梯前往五楼搜查钥匙 → 到保安岗核对停车记录并拿手电 → 前往车库，持续照射逼退黑影 → 对照钥匙上的车牌找到车辆，原地开锁 → 完整播放启动演出 → 实际驾驶、避障并经过两个出口 → 显示汽车真结局。

这是预先知道路线的自动玩家，不是人类初见实况或盲测。脚本会读取地图、碰撞、当前位置、威胁状态和已获得的调查记录，用来规划路线和决定按键。随机天赋、钥匙掉落和异象仍由游戏决定；没有固定随机种子，也不承诺每次结果或时长相同。

所有行为都通过正常的键盘事件和鼠标拖动事件进入游戏输入处理：移动、转向、开门、上下楼、搜查、使用手电、选对话和驾驶。脚本不修改位置、时钟、SAN、背包、存档或危险状态，不调用调试功能和结局函数。死亡、寻路失败、超时或页面报错会让本次录制失败，保留记录，不会自动复活、读档拼接或把失败标成通关。

## 输出与检查

| 文件 | 内容 |
| --- | --- |
| `playthrough.mp4` | 通关成功后生成的完整成片，960×540，H.264 + AAC，原速播放，无剪辑。 |
| `gameplay.webm` | Playwright 直接录下的浏览器画面，包含游戏 HUD、开场和结局。 |
| `game-audio.webm` / `game-audio.mka` | 从游戏 Web Audio 输出旁路录制的实际声音；后者仅重新封装。 |
| `run.json` | 源提交、生成器哈希、画质、逐次键鼠输入、阶段记录、每秒状态观察、最终结局、页面报错、成片哈希。 |
| `last-frame.png` | 录制结束时的完整页面截图；失败时用于定位问题。 |
| `index.html` / `playthrough-summary.json` | 带章节跳转的观看页面和轻量摘要。 |
| `playthrough-run.json.gz` / `playthrough-poster.jpg` | 完整操作日志的压缩副本，以及从录像中提取的封面。 |

成功后可在输出目录运行 `python3 -m http.server 8000`，打开 `http://localhost:8000/` 观看。章节时间取整到秒，仅用于导航；没有改变原始录像。

画面角落标明「脚本操作 · 正常规则」和当前阶段，保留游戏原有的 HUD 和提示。原声与浏览器录像分开捕获，编码时按记录末端对齐并记下偏移量；没有用宣传片配乐代替游戏音效。编码只改变格式和压缩率，不加速，也不截去等待、搜查或遇险过程。

WebGL 在无 GPU 环境中可能出现低帧率；录制器不通过关闭游戏主循环、手动推进模拟或提高移速弥补性能。游戏本身的暂停、演出、对话与慢帧处理保持原样。成片是一次成功的示范路径，不代表所有天赋、异象或路线都经过完整验证。

## 代码分工

- `capture.py`：宣传片和游玩录像共用的服务器、Chromium 配置。
- `playthrough.py`：新浏览器档案、正常点击开局、实时录制、结果检查、日志和 MP4 编码。
- `playthrough.js`：输入操作、只读寻路、常见危险处理和汽车驾驶。
- `game-audio.js`：旁路连接游戏音频输出，不改变原本的扬声器连接。
- `example.py` / `playthrough.html`：核对成片哈希，生成观看页、章节、日志压缩包和封面。
- `render.py` / `shots.js` / `score.py`：第二版宣传片流程继续单独使用；第一版在 `v1/` 存档。

这些文件仅由制作脚本加载，游戏主页不加载自动玩家或录音代码。中间文件保存在已忽略的 `video/build/` 下。
