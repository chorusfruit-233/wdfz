# 好友联机连接原型

当前版本是**连接原型**：2–4 名玩家可以建立房间、准备、进入校园并看到同一区域的队友。它只转发角色位置和外观状态；剧情、背包、时间、门、异象、怪物与结局仍各自在本机运行，暂不能合作通关。客户端提交的位置尚未由服务端做碰撞校验。

联机原型不会覆盖单人存档和结局记录，但本身尚不提供联机存档。刷新页面可在短时间内恢复原房间身份，角色和本机剧情会重新开始；关闭房主程序会结束房间。

## 准备

1. 找一位能在整个测试期间保持开机的电脑作为房主；它运行房间程序，不需要购买云服务器。
2. 房主安装 Node.js 20 或更新版本。下载项目后，在仓库目录执行 `npm ci`；依赖安装只需在首次使用或依赖变化时进行。
3. 异地成员可使用 Tailscale、ZeroTier 等工具加入同一虚拟网络。所有使用浏览器的设备，包括手机，都需要能访问房主的虚拟网络地址；组网工具的账号、费用、可用性及中继取决于服务商和实际网络。

## 启动与加入

在房主电脑的仓库目录执行：

```bash
npm run host
```

默认只监听 `127.0.0.1:8765`，适合本机验证，朋友无法通过这个地址连接。异地联机时，先在组网工具中查看房主的虚拟 IPv4 地址，再指定它。例如：

```bash
npm run host -- --host 100.101.102.103 --port 8765
```

`100.101.102.103` 只是示例，必须换成房主电脑实际分配的虚拟网地址。若使用 Tailscale，可在应用中查看，或通过 `tailscale ip -4` 查询。若启动提示地址不可用，先确认该地址已分配给本机；若队友无法连接，检查组网授权、网络连通和房主防火墙对该端口的设置。

1. 房主用浏览器打开 `http://房主虚拟网地址:8765/`，选择「好友联机 · 原型」，填写昵称并创建房间。
2. 将面板上的邀请地址和房间码发给朋友。房主也应使用虚拟网地址打开页面：若从 `127.0.0.1` 打开，复制出的邀请地址只能在各自设备上指向自己。
3. 朋友在自己的虚拟网络设备上打开同一地址，填写昵称和房间码加入。邀请地址包含房间码，可自动填入；房间码本身不能定位房主。
4. 所有人点「准备」，房主点「开始连接测试」。房间最多 4 人，人数包含房主；开始后暂不支持新人中途加入。
5. 同一区域可以看到队友和昵称。切换区域后只显示同一区域的角色；原型中的其他游戏状态仍不同步。

房主关闭浏览器但保留房间程序时，其他人可以继续连接；房主电脑休眠、断网或房间程序退出会断开所有人。需要结束服务时，在房主终端按 `Ctrl+C`。

房主程序同时提供游戏页面与 WebSocket，应从房主地址打开页面。GitHub Pages 的 HTTPS 页面不能直接使用本原型的明文 `ws://` 连接；部分浏览器功能需要安全上下文，实体设备兼容性仍需验证。程序只提供游戏所需文件，不提供项目中的 `.git`、源码服务目录或存档文件。

## 验证与故障排查

```bash
npm run test:multiplayer
PYTHONPATH=tests python -m unittest -v test_multiplayer
```

前者覆盖房间协议、人数限制、重连和共享移动数学；后者用两个浏览器验证开房、移动、重连、触屏面板及单人存档隔离。两者均在本机运行，不能证明真实异地虚拟组网、手机浏览器或高延迟网络已经通过。

- **连接失败**：确认双方已加入同一虚拟网络，访问的是房主虚拟网地址及正确端口，而不是 `localhost` 或 `127.0.0.1`。
- **房间码错误或房间已结束**：确认房主程序仍在运行，重新复制地址和房间码；重启房主程序会创建新房间。
- **断线**：程序会尝试重连；服务端暂留角色名额约 60 秒。超过时限、房间进程重启或使用新的浏览器会话时，需要重新创建或加入房间。
- **看不到队友**：确认双方均已准备并开始，位于同一个游戏区域。死亡或躲进柜子时角色暂时隐藏。
- **不能一起完成剧情**：这是原型当前的功能边界；共享状态、危险、物品及结局仍需按[多人联机规划](计划-多人联机.md)实现。
