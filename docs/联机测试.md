# 好友联机共享探索原型

当前版本是 **M2 共享探索原型**：2–4 名玩家可建立房间、准备、进入校园并看到同一区域的队友。房主程序统一管理校园时间、门、容器搜索、物品实例及各自背包。玩家可以把东西丢在地上，让队友拾取；暂不能合作通关。

剧情、异象、怪物、NPC、个人 SAN / 体力 / 违规等仍在本机运行。打开菜单会停止本人的个人模拟，但公共时间与队友继续；个人死亡不能回退全队时间。快进时间的活动、未适配设施、投币、请假和结局暂未开放。客户端上报的位置尚未由服务端进行完整碰撞或速度校验，不能把距离检查理解为已完成防作弊。

单人存档和结局记录保持独立。房间运行期间，刷新可在约 60 秒内恢复原身份、背包、剩余物品效果和公共状态；位置、SAN、违规、天赋与个人剧情会重新开始。房间进程关闭后，这些内存状态会丢失，尚无联机持久化存档。

## 准备

1. 找一位能在整个测试期间保持开机的电脑作为房主；它运行房间程序，不需要购买云服务器。
2. 房主安装 Node.js 20 或更新版本。下载项目后，在仓库目录执行 `npm ci`；依赖安装只需在首次使用或依赖变化时进行。
3. 异地成员可使用 Tailscale、ZeroTier 等工具加入同一虚拟网络。所有使用浏览器的设备，包括手机，都需要能访问房主的虚拟网络地址；组网工具的账号、费用、可用性及中继取决于服务商和实际网络。

## 启动与加入

在房主电脑的仓库目录执行：

```bash
npm run host
```

默认只监听 `127.0.0.1:8765`，适合本机验证，朋友无法通过这个地址连接。异地联机时，先在组网工具中查看房主的虚拟 IPv4 地址，再指定它。例如：

```bash
npm run host -- --host 100.101.102.103 --port 8765
```

`100.101.102.103` 只是示例，必须换成房主电脑实际分配的虚拟网地址。若使用 Tailscale，可在应用中查看，或通过 `tailscale ip -4` 查询。若启动提示地址不可用，先确认该地址已分配给本机；若队友无法连接，检查组网授权、网络连通和房主防火墙对该端口的设置。

1. 房主用浏览器打开 `http://房主虚拟网地址:8765/`，选择「好友联机 · 原型」，填写昵称并创建房间。
2. 将面板上的邀请地址和房间码发给朋友。房主也应使用虚拟网地址打开页面：若从 `127.0.0.1` 打开，复制出的邀请地址只能在各自设备上指向自己。
3. 朋友在自己的虚拟网络设备上打开同一地址，填写昵称和房间码加入。邀请地址包含房间码，可自动填入；房间码本身不能定位房主。
4. 所有人点「准备」，房主点「开始共享探索」。房间最多 4 人，人数包含房主；开始后暂不支持新人中途加入。
5. 同一区域可以看到队友和昵称。某人开门后，其他人也能通过；队友在其他楼层时，公共状态仍会保留。

房主关闭浏览器但保留房间程序时，其他人可以继续连接；房主电脑休眠、断网或房间程序退出会断开所有人。需要结束服务时，在房主终端按 `Ctrl+C`。

房主程序同时提供游戏页面与 WebSocket，应从房主地址打开页面。GitHub Pages 的 HTTPS 页面不能直接使用本原型的明文 `ws://` 连接；部分浏览器功能需要安全上下文，实体设备兼容性仍需验证。程序只提供游戏所需文件，不提供项目中的 `.git`、源码服务目录或存档文件。

## 物品协作与时间

- 每人从一张独立的学生证开始，背包最多 8 种，同一种不能携带两件。物品具有独立实例 ID，UI 仍显示物品名称。
- 抽屉、柜子、货架和试卷堆的翻找由房主计时 0.8 秒。走开、切区、躲藏、断线或打开面板会中断；未完成时不生成结果。同一容器同时只允许一人搜索。
- 每个容器只生成一次结果。满包或已持有同类物品时，抽到的物品留在原处，队友可再来拿；不会通过重试重抽。已拿走的容器不会再次发奖。
- 已接入的固定来源：服务器铜线圈、显微镜透镜、地球仪罗盘、一楼讲台粉笔、化学实验台护目镜、保安柜台手电、供桌硬币。每处来源共享且只取一次；离心机等其他设施仍待适配。
- 在背包中选择「丢弃」，或使用原有丢弃键，将物品放到当前位置；队友靠近并面向物品，看到「拾取」后按交互键。物品显示为地面标记和名称。钟楼旋梯等高处暂不能丢弃或远程交互，需回到平地。
- 药片和士力架只能消耗一次，30 秒有效期由房主记录，刷新不会重新给满时长；SAN 收益和体力计算仍属于本机模拟。只读物品、地图和手电保留本地操作。
- 正式退出或断线名额到期时，背包物品放到最后位置供队友拾取；无法在高处合法放置时，回收到教学楼一楼初始走廊。短时断线期间保留原背包，不重复掉落。
- 公共时间沿用课表流速和「先辈」的慢速十秒窗口。打开菜单、房主关闭浏览器或队友在不同区域均不会停止它；所有成员断线时暂停，身份保留期内恢复后继续。不能通过睡觉或活动菜单让全队跳时。

## 协议与代码边界

连接协议版本为 **2**，旧客户端会被要求更新。资源由同一房主地址提供，避免混用旧的单人页面。

| 消息 | 作用 |
| --- | --- |
| `hello / welcome` | 创建、加入、凭证恢复；开始后返回当前公共世界和自己的背包。 |
| `ready / start / started` | 准备与开局；每人取得自己的初始物品实例。 |
| `pose` | 约 20 Hz 上报位置与是否正在操作；服务端绑定连接身份，不接受指定其他玩家操作。 |
| `op` | 携带 `epoch`、递增 `seq` 和 `action`，执行门、搜索、拿取、丢弃、拾取、使用或消耗。 |
| `result` | 返回序号、成功状态、错误码、当前公共世界与自己的状态。 |
| `world / self / clock` | 分别同步公共变化、个人变化与约 4 Hz 时钟；背包明细只发给本人。 |

`server/session.js` 是本轮已迁移规则的权威来源。搜索随机数只在房主生成；服务端校验区域、交互距离、网格墙与关闭的门、目标类别、物品归属及容量。家具精确碰撞、NPC 占座、移动速度、区域切换和生存规则尚未统一迁移。

物品操作绑定实际实例 ID。每名玩家保留最近 256 个操作结果；相同序号和内容重发返回原结果，更改内容会拒绝，已淘汰的旧序号也不会再次执行。客户端暂存待确认操作，短时重连后重发；状态版本防止旧响应覆盖新背包。该机制不会把本机效果演出当作再次发奖的依据。

房主保存的共享状态目前只在内存中。协议中的恢复与去重不等于崩溃恢复；进程重启、恢复凭证失效或超过身份保留期后，都不能承诺接续旧局。

## 验证与故障排查

```bash
npm run test:multiplayer
PYTHONPATH=tests python -m unittest -v test_multiplayer
```

前者覆盖房间协议、人数限制、共享时钟、搜索中断、满包保留、竞争拾取、操作去重、物品归属和共享移动数学；后者用两个浏览器验证开房、移动、跨区、开门、物品交接、刷新恢复、触屏面板及单人存档隔离。浏览器自动化会布置位置以聚焦协议，不能作为自然合作通关证据。两者均在本机运行，不能证明真实异地虚拟组网、手机浏览器或高延迟网络已经通过。

2026-10-29 本机验证：Node.js 房间与共享规则测试 19 项全部通过；Python 浏览器及工具回归共 148 项，147 项通过，1 项因 Chromium 管理策略禁止 `file://` 而跳过。双人测试使用同一本机的两个 Chromium 浏览器上下文，包含丢失丢弃确认后自动重连重发、地面物品不重复、队友拾取以及刷新后保留原物品实例。另有禁网本地资源加载检查通过；未进行真实异地组网或实体手机测试。

- **连接失败**：确认双方已加入同一虚拟网络，访问的是房主虚拟网地址及正确端口，而不是 `localhost` 或 `127.0.0.1`。
- **房间码错误或房间已结束**：确认房主程序仍在运行，重新复制地址和房间码；重启房主程序会创建新房间。
- **断线**：程序会尝试重连；服务端暂留角色名额约 60 秒。超过时限、房间进程重启或使用新的浏览器会话时，原身份无法恢复。已开始的房间不能重新加入，需要房主和队友结束旧局后重新开房。
- **看不到队友**：确认双方均已准备并开始，位于同一个游戏区域。死亡或躲进柜子时角色暂时隐藏。
- **不能一起完成剧情**：共享探索暂未接入统一剧情、危险和结局，后续步骤见[多人联机规划](计划-多人联机.md)。
