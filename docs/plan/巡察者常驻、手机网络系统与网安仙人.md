## 2. 唯一时间口径与事件顺序

### 2.1 实际游玩运行秒

新增唯一权威累计量 `activePlaySeconds`。按已接受的模拟步 `dt` 增加，不读取系统墙钟计算离线收益，不用 `setTimeout(600000)` 决定结局，不把 `advanceGameTime()` 的游戏分钟折成真实秒。

| 场景 | 新运行秒与电量／任务／30 秒复生／600 秒停机 | 校历 |
| --- | --- | --- |
| 正常探索、站立、躲柜、手机打开或收起 | 推进 | 沿原规则推进 |
| 新服务器终端、输入 Linux 命令、软键盘打开 | 推进 | 推进 |
| 学生会检查、一般异象、可操作的驾驶 | 推进 | 沿原规则推进 |
| 正常电梯乘坐、可操作的特殊空间 | 推进，不能被主循环提前 return 漏掉 | 沿原空间规则；`noClock` 仅冻结校历 |
| 暂停、手册、普通冻结选择框、原贪吃蛇 | 停止 | 沿现有暂停规则 |
| 切后台、退出、读取／保存过程、未开始游戏 | 停止 | 不补离线时间 |
| 开场／死亡／结局正式 CG | 停止 | 停止 |
| 睡觉、吃饭等一次性跳过游戏分钟 | 不补对应运行秒 | 只推进校历并处理原日程事件 |

例：终端界面内帮助页属于终端，不冒充普通手册来冻结世界；打开真正暂停或随身手册才冻结。原贪吃蛇世界暂停，因此也不能用其冻结期间免费充电、下载或等待停机。课堂“整理笔记”沿用连续调用完整模拟步的加速方式，所接受的模拟步会推进运行秒；它与只跳校历的吃饭、睡觉不同。

计时精度使用未取整秒；显示可取整。允许差异不超过一个已接受模拟步。后台恢复不追赶离线时长，长卡顿遵守主循环步进上限，不按渲染帧率改变耗电速率。

### 2.2 同步推进与同帧边界

每个模拟步只调用一次新系统更新，并放在驾驶／电梯等分支的提前返回之前。顺序必须显式约定：

1. 固定本步输入、连接状态、所在子区域，处理合法物品操作与已到期的空间转移。
2. 将本步切到最近的任务完成／电量耗尽／复生／停机边界；按相同实际供电时长推进电量和手机任务。
3. 已完整获得所需供电时长的任务先结算成功，再切换下一任务；电量同时归零不撤销已经完成的阶段。剩余步长继续按新负载计算。
4. 完成移动、危险、检查、救命／预知梦和死亡结算。
5. 若停机到期，最后检查玩家仍存活、没有已选定结局，才原子提交《网安仙人》。同帧真实死亡优先，预知梦先清空倒计时；药丸／免疫挡下则仍算存活。

保存、退出和恢复不得重复执行边界事件。任务用身份标记和状态转移防重入；表现层只能读结果。

## 3. 世界级常驻巡察者

### 3.1 状态、位置与信息权限

一个全局实体，在新局世界初始化时生成；开场尚不能操作时不推进。正常运行不再存在“随机等多少秒后在玩家附近刷出”的流程。30 秒符纸复生是唯一明确的临时消失例外。

采用正交状态，不再让旧 `PAT.locked` 同时代表全部行为：

- 实体状态：`active / banished`。
- 行为状态：`patrol / investigate / chase / search / return / transit`。
- 追踪策略：`ordinary / permanent`。
- 玩家当前压力：由同场景、距离、遮挡、捕获资格计算，不能由 permanent 布尔值直接等价得出。

权威位置保存 `sceneId + floor + localPosition + connectorProgress`；室内外局部坐标不直接相减。离屏仍推进，玩家切场景只创建或销毁当前场景模型，不能重置敌人位置。任何时刻实体总数不超过一只。

感知权限：普通巡逻不知道玩家的实时位置；普通直接目击才能更新 `lastSeen`；区域警觉只提供 `regionId`；无线破解按 §6.2 每 15 个有效运行秒提供一次静态快照，不能持续读取玩家移动；只有永久追踪接口允许持续读取玩家全局实时位置。寻路函数必须接收目标场景，不能隐式使用当前 `S.room` 或当前渲染模型的碰撞缓存。

### 3.2 固定路线与最高效覆盖

**效率定义（实施取值）：在覆盖指定楼层走廊、连接口及校园公共通路的约束下，最小化一轮总通行时间；不是最快扑向玩家，不得根据玩家位置改巡逻路线。** 不假称当前已经测得全地图最优坐标路线。

首版覆盖：教学楼、行政楼、实验楼各 1—5 层公共走廊，两条二楼连廊，以及校园室外公共通路。其他建筑覆盖入口外侧，不把宿舍房间、食堂、车库、天台、隧道和特殊维度加入日常扫荡路线。普通追击和永久追踪的可进入边界另见 §3.5。

固定出生点：行政楼一楼楼梯旁预设合法节点 `admin1/stair_landing`，不能从玩家位置反推；不得位于开局教室。路线总览：

```text
行政楼 1F 出生点
→ 行政楼 2F→3F→4F→5F→4F→3F→2F（各层完成走廊覆盖）
→ 连廊① → 实验楼 2F
→ 实验楼 1F→2F→3F→4F→5F→4F→3F→2F
→ 连廊② → 教学楼 2F
→ 教学楼 3F→4F→5F→4F→3F→2F→1F → 室外
→ 校园南段／东段／北段／西段公共巡回 → 行政楼 1F
```

室外需覆盖教学楼、钟楼、花园、南北宿舍与食堂入口外侧、南门、垃圾房外侧、东侧通路、北门与保安岗、操场和器材室外侧、车库入口外侧、西小门及行政楼入口。上述为覆盖与连通骨架，不按建筑中心直线穿楼。

落地方法：先由真实碰撞和连接点生成可通行加权图；将所选覆盖骨架建成连通无向巡回图，边权为最短合法路径耗时。对该固定图采用最短路、奇度点最小权配对及欧拉巡回生成最小代价闭合覆盖路线；同代价按节点 ID 固定排序。竖向尽端支路一次完成上行／下行，避免反复跨栋。

上面的宏观访问顺序是初始骨架；若测量证明调整顺序更短，可由离线生成器固定输出更优序列，提交 `routeVersion`、边权、总耗时、覆盖清单和与初始骨架的比较。运行时不重新随机排路。最优性仅针对已选加权骨架，不宣称优化了所有可能房间布局或玩家体验。每层至少覆盖所有教室／办公室门口可观察的走廊节点；返回途中不用重复整段扫走廊。夜间不刷出第二只，也不无提示重置位置。

追击／调查结束后到可达的最近巡逻节点接回既定方向；距离并列按固定节点序裁决。警觉事件可以打断巡回，但不能永久饿死待处理队列。

### 3.3 常驻不等于全天攻击

普通索敌资格保持旧逻辑的本意：上课／考试时在教学、行政、实验楼 1—5 层索敌；白天校长办公室内部、网络中心指定报警区不受普通课表限制；夜间普通索敌限室外。坐在原座位、有效假条、有效外出登记按既有例外判断，普通外出登记不保护这些报警区、考试和夜间。

实体可以经过当前不允许普通索敌的地方，不会因此消失。正常目标资格终止后停止普通追击并返回巡逻；保护是停止普通敌对行为，不是移除实体。永久追踪忽略上述课表与豁免。

不新增视野锥或奔跑声引怪；保留现有 360° 距离＋遮挡侦测，避免本次同时改变另一套潜行规则。

### 3.4 普通追击、搜索与背对移除

普通追击可沿真实连接跨楼层／建筑。目击中更新位置；被遮挡后只能追最后目击位置，不能在失去视线的 2.5 秒宽限内偷读玩家新坐标。连续跟丢超过 2.5 秒后取消普通锁定，前往最后位置搜索，停留 3 运行秒后处理队列或返回路线。

普通储物柜有效性沿用“是否被直接看到进入”；躲柜位置记忆只用于后续调查，不能凭记忆把未被目击的玩家判为已发现。普通追击失效也不移除常驻实体。

完整删除背对静止脱离、`still` 计时、背对时不逼近分支和对应存档恢复、死亡提示、课堂提醒、Wiki、录像脚本和测试期待。背对不再有任何特权。

### 3.5 穿门与跨区域通行

巡察者能连续走过普通门及上锁的门，**不消耗玩家钥匙、不替玩家开锁、不修改 `OPENDOORS`**。玩家仍需要钥匙；关闭的门仍遮挡视线，因此关门可以暂时断视线，不能当作物理屏障永久挡怪。

仅从注册门洞通过；墙、柜体、桌椅、楼板和未定义空间边界仍参与碰撞。穿门按逐帧步行距离消耗预算，不再等整段门洞距离凑齐后跳过，也不反复刷新 0.22 秒抓捕保护。非栅格起点接回路径时校验整条连接线段，不能抄过墙角。过门本身不授予普通敌人新位置情报。

楼梯与场景入口使用显式图边，不调用会移动玩家的 `enterRoom()`。实施取值：普通楼层相邻楼梯边 2 运行秒／层，连廊和室外按实距与运动速度计时；不得因离屏把上楼或穿楼变成零耗时。首版不依赖呼梯排队，用楼梯连接追逐；玩家在轿厢中，永久目标可以等待／赶往实际停靠楼层，不能隔着轿厢判定接触。

日常路线不进入上述特殊空间，但永久追踪不得被一个场景切换洗掉。所有可停留空间必须有导航适配：普通建筑和地下空间沿门／楼梯进入；隧道与特殊维度按其已注册连接和可行走面跟随。对于暂不可进入的移动载具，追踪保持，不能隔空间扣伤害。不得拿“守在一个永远碰不到玩家的出口”冒充已支持永久追击；特殊空间适配未通过前整项不能标为完成。已有其他敌人不被本次替换。

### 3.6 运动参数、预警与符纸

按 2026-11-03 最新补充，巡逻速度 16、追击 31、视距 135、抓捕距离 19 保持（内部单位；换算依现有 `U2M`）；巡逻、追逐、搜索、无线／区域调查和归队按 `speed × dt` 连续移动。删除旧 1.1／0.75 秒短瞬移节拍。只有室外普通巡逻可沿已规划道路长瞬移赶路，实施取值为路径距离 240–480、成功后冷却 8 运行秒，起止处避开玩家附近通路及相邻入口，不进入室内；调查和追逐不得借此抄近贴脸。真正长瞬移、显式跨场景到达和复生保留 0.22 秒宽限，步行不续期。抓捕仍额外要求有效局部锁定，防止直接碰到尚未提示的普通巡逻者就无提示失败。

删除旧巡察随机间隔、45 秒自动消失和“切区域结束巡察”的调度。校园压力不再缩短已经不存在的刷新间隔；现有异象与环境压力不动，也不偷偷改成提高巡察速度。

旧生成预警改为接近预警：同区域或相邻入口按真实距离／路径方向提前播放两短一长灯光和脚步，目标提前量沿用 3.6 秒；新生与符纸复生在固定节点有同样前兆。灯光来源跟实际位置走，不在全校同时泄露方位。

符纸仍自动使用：**局部锁定将成立时**消耗一张并消灭巡察实体；远隔校园的 permanent 标记本身不消耗符纸。实体消失后记录 `respawnRemaining=30`，计时期间不抓捕、不产生实体 SAN 压迫，定位应用显示信号暂不可用。

30 运行秒后在固定出生节点复生，保留永久追踪标记和未处理的区域队列；若永久标记仍在，立刻采用永久追踪策略。复生前 3.6 秒在出生区域预警，不修改倒计时来偷偷延迟复生；复生落点有 0.22 秒抓捕宽限。符纸是实打实消灭，不写成击退或仅失去目标。普通玩家不会凭一次符纸让本局永久无敌。永久追踪对柜内玩家的局部锁定以已知柜门位置及实际接近为准，不复用 `patSees()` 对 `HIDE.on` 的一票否决；符纸在这类近距离检查中也可自动生效。

### 3.7 特殊区域通知与队列

**当前范围：**行政楼五楼六间办公室内部，以及网络中心「终端操作区」「核心机房」。后两处按用户最新要求显式加入，替代 Q08 早期的“网络中心不报警”。共同名单与边界在 `content/patrol-zones.js`，网络中心黄线与告示标出区域。公共走廊、楼梯、电梯口、门洞和学生机房均不在其中，不把实验楼整层扩张成自动报警区。

进入时只报告一次区域标识、顺序和发生运行秒，不携带玩家坐标、离开方向、当前房间或“仍在里面”字段；网络中心进入时有字幕反馈。即使没有看见玩家也优先安排调查；离开不发敌人可见通知，停留不重复报点。该范围以旧白天特殊资格为准，夜间不凭此新建室内普通敌对资格；这与无线破解每 15 秒提供精确静态快照是两种独立来源。

优先级：永久追踪 ＞ 已建立的直接追击／丢失搜索 ＞ 最近无线快照调查 ＞ 区域 FIFO 队列 ＞ 柜子记忆 ＞ 固定巡逻。当前调查被追击打断时保存，追击结束再继续队首；后来通知不能把正在调查的目标换成最新玩家位置。对同一尚在排队／调查的区域合并重复进入，不刷新原排序；调查完成后再次进入可以形成新事件，防止门槛反复穿行无限刷队列。

调查路径为区域内固定合法观察节点，实施取值：到达后用 6 运行秒主动检查，未见玩家则结束调查；可用真实目击重新锁定。区域通知从始至终不能等价为锁定。例：玩家进入办公室 A 后离开并进入 B，巡察者仍先去 A，再去 B，不因玩家已离开 A 就跳过。

### 3.8 永久追踪与局部压迫

永久追踪始终知道玩家所在场景和坐标，不因躲柜、遮挡、切楼、课间、假条、重新登记或普通卡路超时解除。寻路失败要重规划并上报诊断，不允许沿用“卡住六秒就取消永久追踪”。敌人必须接近到合法抓捕范围才造成接触后果，不能跨墙、跨层或跨维度远程抓捕。

基础追逐 SAN 消耗仍为 0.35／运行秒，但仅在同可比空间、视距范围内且有直接威胁视线时生效；被已目击进入的柜门检查／永久追踪逼近柜门时按实际威胁处理。远处 permanent 不扣该项、不强制持续红屏。红光与心跳由局部压力渐变产生。柜内基础 0.18／秒也只在本区域存在近距离巡察威胁时使用，不能因敌人全局常驻就全校柜子永远扣 SAN。校庆等既有持续伤害修正仍通过 `sanDrain()`。

## 4. 外出登记、检查责任与救回

### 4.1 第一天

`day===1` 禁用手动外出登记和合规检查自动许可；在公共授权入口统一拦截，不能只把按钮变灰。移交单、钥匙线索、粉笔和补给线索正常保留。假条不是讲台登记，本次不顺带禁用假条。

第二天起恢复手动登记及自动续签，且二者都形成检查责任。旧档第一天残留的外出许可作废并给迁移说明，不创建追溯缺席惩罚。首次开局／读取迁移前后都不得偷偷自动补登记。

### 4.2 责任与许可分开

许可 `until` 继续按校历期限管理；另设责任记录 `dutyId, source, issuedAt, targetCheckId, status`。检查 ID 使用“天数＋12:50/17:50 槽位”，不能拿总违规值或时间差猜测。

手动登记和自动续签均绑定下一场检查；17:50 之后的登记责任绑定次日 12:50，许可仍可能先于熄灯到期。到期不删除责任。重复对同一下一场登记合并为一项责任，不能覆盖旧承诺以推迟归还。

下一场有效检查开始时按既有 `inClassroomHere()` 判在场。履约后结束当前责任；若自动续签获准，则建立新的下一场责任。该场的移动违规／注视扣 SAN 不触发永久追踪。只有匹配责任的有效检查最终写入缺席记录且完成该项违规结算，才发一次 `RegisteredAbsence`。

系统取消／过期的检查不判缺席，责任顺延到下一场有效检查并更新 UI；不是默默免除所有未来责任。未登记者仍承担旧检查处罚，但不会凭单纯缺席得到本次新增的永久追踪。

### 4.3 检查调度

删除对 `PAT.state==='idle'` 的依赖。普通巡逻、远处区域调查、远处永久目标标记都不阻塞检查；只有本地实际追逐或现有强制冲突才延期，沿用最多 3 个游戏分钟的排队上限，超限取消该场并顺延责任。

检查开始后沿用 8 运行秒流程及 8 秒散场缓冲。为避免刚开始检查又要求玩家逃跑，普通敌人不在该局部检查区新建直接锁定；永久实体若随后抵达，在局部冲突边界等到检查结束及缓冲完成，仍保留定位和追踪，不被全局冻结。此为实施的冲突保护，不是永久追踪解除，也不能被重复打开 UI 刷新。

保留一分钟自然运行时间的返程广播、检查基础数值与现有日程。恒定巡逻本身不得导致所有检查被取消。第一天的检查照常存在，只是不发自动许可。

### 4.4 永久追踪的生命周期

触发时清晰告知玩家“外出登记后未归，持续追踪已生效”。责任结算先落盘，再改变追踪策略，防止读档复算。

重新登记、假条、就座、离开特殊区域不能解除；符纸消灭实体也不能解除。药丸／免疫真正挡下致命事件后解除永久追踪、清空该次追击与导致处罚的已结算责任，不得下一帧根据旧违规自动重新附加。实体返回普通路线；实施取值：救回后 3.6 运行秒不重新锁定该玩家，避免原地连抓。

预知梦按 §10 全面重置新增进度；正常新局重置；真正死亡结束本局。调试无敌不是正常救回，不应被用作持续清除标记并取得有效速通成绩的手段。

## 5. 手机能源系统与科技党

### 5.1 设备与天赋

新增天赋 `tech`，名称“科技党”：开局获得一部满电手机，所有手机消耗永久 ×2。保留“编程社”，不赋予科技党免 U 盘或免验证题能力。新局仍按原天赋选择制度，不叠加两个天赋。

普通首次获得手机也满电。设备状态按本局唯一设备身份保存，从首次获得且世界运行后耗电；没有获得过不预先扣电。开局发放幂等，正常读档不再次赠机或充满。持有状态、电量、网络资格不绑定到某个背包槽位。

丢弃手机不重置电量；设备已激活后仍按本局运行时间记基础耗电，不得用丢弃暂停耗电。无持有设备时手机任务挂起、不能查询和充电；再次取得手机沿用本局电量与已完成阶段。预知梦属于用户明确指定的整批重置例外。天赋倍率跨存读档、救回与惊醒持续，不影响下一个选择其他天赋的新局。

### 5.2 唯一能量公式

单位为电量**百分点**，不是对剩余电量做指数衰减。令基础速率 `b=100/600=1/6` 点／秒，负载 `a=2` 仅在无线渗透实际运行时，其余为 1；天赋 `t=2` 为科技党，否则 1；输入功率 `c` 由地点／连接决定：

```text
dBattery/dSecond = c - b × a × t
室外／其他地点：c = 0
原教室：c = 0.5 点／秒（30 点／分钟）
机房已接电脑：c = 1/6 点／秒（10 点／分钟）
最终电量钳制到 [0,100]
```

两个充电源不叠加；下载、定位、同步、终端与纸飞机均不增加负载；多个应用也不重复叠加基础耗电。

| 地点／连接 | 普通·无渗透 | 普通·渗透中 | 科技党·无渗透 | 科技党·渗透中 |
| --- | ---: | ---: | ---: | ---: |
| 无充电 | -10／分 | -20／分 | -20／分 | -40／分 |
| 原教室 | +20／分 | +10／分 | +10／分 | -10／分 |
| 机房接电脑 | 0／分 | -10／分 | -10／分 | -30／分 |

对应满电无充电续航：普通 600 秒、科技党 300 秒；无线渗透期间分别为 300 秒、150 秒。手机收起照耗电。

### 5.3 充电行为

原教室指开局玩家座位所属的**那间教室的门内区域**，不是 `teach1` 整层；用座位和门墙划分的子区域判定。站着、移动、使用应用均可充电，不要求就座，不新增座位同化奖励；离开立即停止输入，已充电保留。

固定功率的结果必须向玩家说明：无渗透时普通从 0 充满需 300 秒；科技党需 600 秒。科技党原教室渗透中仍净掉电，不能宣传为“五分钟充满且破解不耗电”。

机房连接学生电脑／教师机后才充电，站在楼层里不自动充。无需容器、无需连接线物品；移动离开连接距离或换场景立即断开。实施取值：连接半径沿现有近物交互距离，保持提示一致，不凭屏幕打开状态判接线。

机房不是快速补电点：普通未渗透时只是维持电量，科技党仍每分钟净掉 10 点；0 电量普通手机在机房也不能净充起来。0 电量任务暂停后按普通负载计算，不能凭开／关机获得免费能量。

### 5.4 断电、恢复与并发

电量到 0 时关闭手机操作界面、停止供电型任务并保存阶段进度；网络资格和已完成容器不删除。不会把服务器已经接收的停机任务取消。

实施取值：低电提醒 20% 和 5% 各一次；断电后充至 5% 自动恢复挂起任务，设置这一门槛避免零点附近每帧启停。玩家可主动暂停无线渗透／下载以积攒电量，再继续；继续不重抽耗时。不把“主动暂停”写成重新开始。

后台任务同一时刻只有一个耗电负载源：无线渗透成功后立即退出 ×2 负载，随后才进入 ×1 的下载；定位、同步可与下载同时使用，不打断下载。任务耗时只累计真正有电且满足运行条件的区间，不能在没电的一步先推进整段任务。

## 6. 网络与手机应用

### 6.1 手机外壳与危险状态

保留纸飞机与原奖励规则，新增“无线渗透”“巡察查询”“门禁同步”“容器状态”。工具类在普通追击、永久追踪及一般异象中允许打开；纸飞机仍按遇险规则禁止或中断。死亡、正式过场、检查／异象的强制选择优先，保存工具页面后关闭，不丢任务。

实施取值：保持原手机姿态——查看时不能移动或环视，世界继续；一键收起立即恢复操作。不能仅因 `PAT.locked` 统一封锁工具；也不新增边跑边看功能。电量为零只允许看到断电提示，不能读最新位置或操作同步。

### 6.2 无线接入与实时定位

无线渗透完全是游戏内任务，无技术操作。首次点击开始时抽取一个均匀的 180—600 运行秒目标，立刻存档；正常读取、断电、关闭页面、暂停后继续都沿用原目标。成功设置独立的 `network.connected`，不设置 `RT.hacked`。

2026-11-03 追加实施：破解每累计 **15 个有效运行秒**，向唯一巡察者发送一次玩家当时的场景、坐标和脚高快照，新快照覆盖旧快照。到达旧位置搜索 3 秒；期间未实际发现玩家则返回原任务，不持续读取玩家的位置。该调查优先于办公室与柜子记忆，低于已有实际目击追逐与永久策略；坐下、假条、外出许可和普通敌对时段不能免除这次调查，但接近预警、视线与实际通路、符纸和检查现场等待照旧。躲柜时仅暴露当时的柜门，之后换柜不会自动更新。

暴露间隔直接由已保存的破解进度推导，不另起可被暂停／读档重置的计时器。手机收起继续；主动暂停、断电、丢弃设备和世界暂停停止累计，恢复后接续。恰在边界完成时先发送快照再转入容器下载，下载与停机等待不暴露。已发出的快照不会因暂停／完成撤回；符纸消灭期间保留，真正救回／预知梦及新局清除。手机无线页显示规则与下一次暴露倒计时，并提示本次位置已经泄露。

网络资格在本局跨天保留，正常救回保留，预知梦清空。成功后立即解锁定位与门禁同步，同时自动开始 60 运行秒的容器下载。

定位应用在每次权威位置变化后实时读取并呈现区域与楼层；不按一分钟轮询、不做人工点击刷新。DOM 仅在显示文本改变时更新，渲染频率不能影响权威位置。界面只给“行政楼／3F”这类信息；连接段显示“连廊①／2F”或“楼梯／2F→3F”，不提供精确坐标、朝向、距离、路径和下一个目标。

手机外 HUD、小地图、手册和通知不得携带实时位置。完成通知只说任务完成；符纸消灭期间显示信号暂不可用，不能冒出第二只敌人或显示虚假的固定位置。

### 6.3 手机远程同步

成功条件同时满足：持有手机、有电、已接入学校网络、`RT.hacked===true`。容器下载完成不是同步前置。实施取值：点击后即时提交，不额外加读条和额外扣电。

成功效果与行政楼三楼一致：`RT.data=true`，记录来源、更新笔记、自动保存。两端调用同一个幂等服务，不能发两次奖励。未先写入白名单时只提示去网络中心，不允许无线成功自动等于白名单写入。

保留机房钥匙、U 盘／编程社、网络中心写入、传统行政楼同步、西小门三题及既有错误惩罚。旧文案“不代替行政楼同步”需更新为准确的“仍须完成同步，可用实体终端或联网手机”。

### 6.4 自动容器下载

无线成功后自动下载 60 运行秒；使用基础负载，不再用无线渗透 ×2。可在收起手机后运行，断电／无设备时暂停，恢复后按 §5.4 继续。完成后仅解锁服务器终端，不自动完成谜题。

“Kali Linux 容器”是叙事中的工具环境；实现为游戏内安装进度、模拟终端和虚拟文件系统，不向玩家设备实际下载发行版镜像或启动系统容器。

## 7. 机房服务器解谜

### 7.1 电脑入口与路线门槛

实施取值：实验楼 3F 的任意学生机和教师机都支持连接手机；沿用它们的既有交互入口，弹出“贪吃蛇／连接手机／断开”等明确选项，不能直接覆盖旧恢复活动。充电不要求网络或容器；新终端要求联网和下载完成。

新结局**不额外要求机房钥匙或 U 盘**，由耗电、运行等待与 Linux 解谜承担成本；白名单和铜线圈路线仍需上锁网络中心。接入电脑不是拆服务器，拿走铜线圈也不会禁用整个网络或使新结局软锁；不得给科技党额外绕过谜题能力。

占课日只禁原“玩电脑恢复 SAN／贪吃蛇”活动，不禁接电和新终端，不封死白名单实体终端。对应广播从笼统“机房不开”改为反映实际限制。网络中心仅两处指定区域进入时报警；学生机、教师机和走廊不因本次扩展而报警。

### 7.2 输入、暂停和退出

新终端独立于 `PC.on`，不沿用贪吃蛇冻结策略。玩家不能移动，巡察、异象、校历、电量和后台任务继续；保留空间声音、边缘危险提示和始终可见的退出按钮。键盘 Esc 或触屏退出立即解除终端输入占用，不吞掉第一次操作。

一般接近警告不替玩家解题或自动关机；强制选择、死亡、正式过场优先关闭终端并保存。断线／断电保存编辑缓冲、工作目录和已完成阶段。重新连接从合法保存点继续，不能通过重新开终端刷新电量／答案。

Android 软键盘出现、输入框聚焦不应被当作切后台；真正文档隐藏才按暂停处理。终端拥有文字输入时，WASD、数字、空格、Ctrl 组合不同时触发角色、快捷物品、跳过或调试功能。

### 7.3 模拟命令与谜题规格

只实现白名单解析器：`help`、`man`、`pwd`、`ls -a`、`cd`、`cat`、`grep`、`head`、`tail`、`sort`、`cp`、`mkdir`、`edit` 与游戏专用 `campusctl`。支持基本引号、绝对／相对路径、明确的有限管道组合；其他语法返回可理解的“不支持”，不伪装完整 Bash。

文件都来自游戏种子生成的只读 `/school` 与可写 `/work`。不得使用 `eval`、`Function`、宿主 shell、真实 SSH、真实漏洞、浏览器凭据、局域网扫描或访问真实服务；模拟命令只读写本局白名单状态。限制输入长度和管道深度，输出转义，不允许富文本注入。帮助说明足够完成任务，但不直接列出本局答案。

谜题结构固定，控制器代号、日志批次、关联标识和验证词按 `runSeed + attemptId` 生成并保存；生成器同时产生唯一可验证答案。有效信息之间逻辑一致，叙事矛盾不能成为多解／无解的借口。普通读档不重抽；预知梦新 attempt 可重新生成。

| 阶段 | 玩家要理解与完成的事 | 线索与判定 | 持久状态 |
| --- | --- | --- | --- |
| T0 环境识别 | 查看路径、列目录、找到工具说明 | `/school/README`、`help`；确认操作范围只在模拟学校服务 | cwd、已读帮助 |
| T1 目标辨识 | 从多份资产清单识别当前试点控制器，排除镜像与过期节点 | 主清单、区域编号和运行批次三方对应，不能只看名字相似 | controllerId、证据编号 |
| T2 日志关联 | 用查找／排序对应同一事务的日志，区分校历与运行秒 | 两套时间字段、相同事务 ID、节点角色；给出可推导的时间口径 | chainId、证据集 |
| T3 依赖分析 | 从服务说明和依赖图确定有序关闭步骤，保留负责执行最后提交的控制层 | 读取三个功能模块的依赖约束，在 `/work` 写停机清单；检查无环与顺序 | manifest、阶段验证 |

以上是高难度线索关联解谜，不是输入一个现实攻击命令即获胜。首次难度来自查找和推理，熟悉命令者能更快操作。`help` 不收费；两级可选提示分别指出证据所在目录和关联方法，提示不改变本局答案。

语法错误、未知命令、错误目标和校验失败不额外扣 SAN／电量，不暗中加警报或终局失败；实际游玩时间与基础耗电照常付出。正式提交前明确告知“必须存活十分钟，手机可断开”。提交必须通过 T1—T4 校验，不能靠直接调用结局或伪造 UI 返回值获得有效速通。

## 8. 十分钟生存与结局仲裁

服务器接受合法请求的一刻开始 600 运行秒，不是从下载完成、进入机房或开始解谜时开始。请求只能创建一次；重复提交返回原任务，不能重置或叠加倒计时。

玩家必须活到倒计时结束。任务已经在服务器运行，所以离开机房、拔线、手机断电、跨天均不停止；暂停、手册、原贪吃蛇、退出和冻结过场则按统一运行秒停止。游戏时钟跳时不会快进任务。

等待期间保留正常世界，不新增未授权的专属追兵、不额外提高巡察速度。手机有电时可查剩余时间；无手机时不额外给实时敌人位置，停机最终完成可通过校园广播与环境表现感知。

允许中途选择既有结局。第一项已经确认的终局拥有本局结算权；其他异步回调全部取消。到期时即使在终端、驾驶或可操作特殊空间，也由全局仲裁安全交接到结局舞台，不要求回机房。正式结局 CG 阶段运行秒已经停止。

药丸／免疫救回后，玩家仍活着，保留已提交任务和剩余秒数，并按 Q11 解除永久追踪。预知梦惊醒取消该任务及其新路线进度，不能把上一段梦里的请求带回；真正死亡取消所有后续结局回调。旧外部备份按备份快照恢复，不额外引入跨存档联网惩罚。

## 9. 公开真结局《网安仙人》

### 9.1 公司与真相层次

虚构公司定名 **AnthroPrank AI（安抄派智能）**，以 A 开头，保留对 Anthropic 名称的戏仿感。全部阴谋与档案仅属于虚构公司的游戏故事，不声称现实公司实施过相关行为，不使用现实商标或伪造现实新闻。

公司档案揭露其把校园里世界作为“行为一致性与秩序对齐”试点，利用名单、门禁与巡察组织观察。玩家能停掉的是这套可操作的控制系统；公司关于自己创造了里世界的宣传与其他档案互相冲突。

设三组可发现矛盾（叙事取值）：

1. 项目创世报告声称异常从第一次部署开始，但导入的旧纸质档案包含更早的同类事件。
2. 宣传报告声称所有巡察行为都由控制器产生，故障记录却承认某次断开控制链后仍收到事件回执。
3. 验收档案声称退出身份已注销，原始记录却把注销解释为“转交上层保管”，并出现无对应签发节点的回执。

这些矛盾支持“公司是阴谋试点的组织者，但未必掌握最本质来源”，不是通过后来一行文字推翻前面的全部探索。它们与解谜必需的技术判定信息分层，避免把叙事不可靠等同于谜题不公平。没有额外隐藏路线前置。

### 9.2 3D 结尾分镜

实施取值：约 16 秒，复用现有校园、服务器与巡察模型；由独立演出舞台驱动，不写坏真实玩家坐标。

| 段落 | 画面与声音 | 叙事作用 |
| --- | --- | --- |
| 0—3 秒 | 机柜指示灯按序熄灭，校园广播停止在一句话中间 | 明确服务器停机已经执行 |
| 3—7 秒 | 走廊灯停止异常闪烁，巡察者在原地失去活动，背景声逐层静下 | 确认玩家确实终止本轮里世界运作，不伪装假结局 |
| 7—11 秒 | 档案在实景屏幕上对照出现，前后部署日期与签发来源矛盾 | 揭露公司试点，同时保留深层疑问 |

最终文字必须逐字为：**您未能完全理解里世界**。它出现在所有结局文字的最后；跳过 CG 也必须保留结局卡这句话。返回菜单／速通成绩等功能性按钮不算额外剧情文字。

### 9.3 公开与速通

新增结局 ID 建议 `cyber`，标为公开 `true`；加入公开结局列表、路线进度、Wiki 剧透折叠和速通类别，不能延续此前助手误称的“隐藏结局”。菜单在未通关时可显示名称与未解锁状态；不提前展示完整谜题答案。

速通继续使用项目既有 RTA 口径，暂停也计速通用时；**RTA 与此次统一的玩法运行秒是两个不同用途的计时器**，不能为保持“统一”而改坏旧排行榜。`cyber` 停表时点是存活倒计时完成并确认结局，不是 T4 提交时。路线／规则版本升级，旧成绩保留但不同规则不混排。新结局公开不授权泄露其他已有隐藏内容。

### 13.5 平衡与自然路线

必须分别记录规则单测、布置条件的浏览器自动化、正常操作完整通关和真实设备体验。不得把设置位置、道具或 `RT` 后到终点的测试称为自然通关。

## 16. 合并后审查与优化（2026-11-03，PR #30）

PR #29 合入 main 后按用户要求复审。逐项对照本计划核对了纯规则（能量公式含「0 电量在机房也充不起来」、无线接入耗时读档不重抽、停机请求只能创建一次）、终端安全（只模拟命令，输出一律按文本显示）、存档域校验、检查责任、巡察者的锁定与抓捕条件、Wiki 保密（`test_wiki_secrets` 通过），没有发现规则偏差。处理了三项：

1. **跨场景追踪的卡顿**：永久追踪跨楼时，巡察者每次重新规划都对起点、终点两组骨架节点逐对重算最短路（`RouteGraph.shortest` 每弹出一个节点都整体排序一次），一次路由约 8 毫秒，三分之二花在这里。骨架图建好后不再变，`PatrolNav` 改为按节点对缓存最短路，结果与直接调用完全相同。本地测量（桌面 Chromium，20 秒跨楼追踪）：超过 5 毫秒的帧从 22 次降到 3 次，平均每帧 0.15 → 0.07 毫秒，单次路由约 3 毫秒。回归 `test_cross_scene_replanning_reuses_skeleton_shortest_paths`。迷宫里的寻路另测：平均每帧 0.2 毫秒、单次远距离寻路约 16 毫秒，未改。
2. **结局演出的着色器与贴图**：原演出加了两盏实时点光源，切段时灯光数目变化会让受光材质重编着色器；文字屏的画布贴图清场时没有释放。随第 3 项一起解决。
3. **结局分镜**：原演出是四个基本静止的镜头轮流切换，没有 9.2 节写的「广播停在一句话中间」「巡察者在原地失去活动」「档案对照出现」「回到普通光线」这些动作。按 9.2 节重做为 16 秒实时 3D 分镜，详见[全死亡方式与结局CG重制](全死亡方式与结局CG重制、隐藏触发时刻校准.md)文末补记；最后文字与结局卡不变。
