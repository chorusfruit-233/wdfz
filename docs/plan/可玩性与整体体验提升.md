# 可玩性与整体体验提升

> 整体状态与维护记录以[计划目录](README.md)为准。
>
> 建档：2026-11-01。评估基线：[main `0d9ebba`](https://github.com/chorusfruit-233/wdfz/commit/0d9ebba3daa012d38eaaf4bc3a5512e1cb8c0b3d)。后续实施记录应注明实际提交和验证环境。
>
> 来源：用户要求评估游戏还缺少什么才能提高可玩性与整体质量，随后要求将全部建议汇总到一个计划 Markdown。本文集中规划首局体验、调查记录、路线玩法、资源决策、失败学习、空间辨识、操作与视听、重玩与叙事，以及真人和真机验证。
>
> 范围：3D 单人校园规则怪谈。本文是后续实施与验收依据，方案示例和试验目标不代表代码已经实现或体验已经验证。包含内部路线设计，不将隐藏路线、触发时刻、未发现内容或可反推隐藏内容的计数同步到玩家 Wiki。

## 1. 目标与实施原则

把「探索 → 发现 → 判断 → 冒险 → 反馈 → 调整下一步」做成持续有吸引力的循环。玩家在一段游玩结束后，能够说清自己发现了什么、为何做出选择，以及下一次准备如何行动。

本计划关注五个结果：

1. 新玩家能自行开始调查，形成第一个具体目标。
2. 探索所得能被理解、记录和利用，观察与准备能够影响行动结果。
3. 资源、时间和路线选择具有不同收益，熟悉游戏后仍存在值得考虑的取舍。
4. 失败带来可用的经验，重试中的主要时间花在尚未掌握的挑战上。
5. 桌面和手机能够稳定、舒适地完成核心流程，结论有真人和真实设备的证据。

实施优先使用现有校园、物品、异象、音效和路线，先打磨一条普通逃脱路线，再将验证有效的设计扩展到其他路线。新增地图、死法、画质档、宏观 AI 导演或大型 NPC 系统不列为本计划的默认依赖；多人原型的后续接入另行协调，不阻塞单人体验改进。

已确认的课表、学生会检查、夜间规则、同化满值结果、假正常笑值机制、垃圾桶死亡结果、梦魇死亡与删档规则，以及隐藏路线约定，继续作为边界。候选新模式或数值调整要记录改变的具体规则、原因和证据，不能在普通体验优化中隐含替换。

| 编号 | 优先级 | 工作包 | 主要交付 | 主要依赖 |
| --- | --- | --- | --- | --- |
| G1 | P0 | 首局小目标与体验切片 | 一段自然可玩的开局调查，能够导向普通逃脱路线。 | 当前规则与路线基线；G2 最小记录能力。 |
| G2 | P0 | 调查笔记与路线进度 | 具体线索复读、证据关系、已知进度与下一步候选。 | 线索来源梳理、存档边界。 |
| G3 | P1；首条路线试点前置 | 路线中的观察与局部挑战 | 首条路线两处有价值的观察／操作，随后扩至其他路线。 | G1、G2；既有路线逻辑。 |
| G4 | P1 | 资源、课堂与选择收益 | 资源用途和选择收益表，小范围可对照的调整。 | G2、G3 的路线目标；G9 的试玩反馈。 |

## 4. G1：首局小目标与前十分钟体验

### 4.1 目标

玩家获得控制后，通过调查形成第一个具体目标，理解交互、查看物品、记录线索和应对危险的基本方法。优先打磨约 5–10 分钟的体验；这是原型长度建议，不是已经验证的完成时间或强制倒计时。

### 4.2 建议流程

| 阶段 | 场景与玩家行动 | 应获得的反馈 |
| --- | --- | --- |
| 注意到异常 | 在初始座位附近看到与日常不符的信息，起身或查看课桌。 | 发现一条具体疑问，知道附近有可交互目标。 |
| 第一次调查 | 前往容易辨认的教室内物件或邻近空间验证信息。 | 获得可靠线索，手册中能重新找到它。 |
| 第一次准备 | 利用已经理解的物品、空间或遮蔽物。 | 理解至少一种可主动控制的风险因素。 |
| 第一次风险 | 接触有清晰信息和可行应对的威胁，允许观察、等待或退回。 | 能解释自己为什么安全、受损或失败。 |
| 决定下一站 | 线索自然指向一个普通路线的地点。 | 玩家能够自行说出准备去哪、希望验证什么。 |

原型先选择一条普通逃脱路线，建议以车库路线验证「准备—辨认车辆—应对威胁」的连续性；它的前置取物、校长办公室探索和实际路程都算入体验，不能靠调试发物品或传送跳过。若这一范围无法形成清晰开局，可先用白名单路线测试 G1／G2，并将车库作为 G3 的局部试点。选定路线及理由写入实施记录。

### 4.3 实施要求

- 使用场景中的文字、物件和行动后果建立目标，按动作需要提供简短操作提示。
- 首条关键线索能够被各天赋的新玩家正常获得；阅读型引导不要依赖随机掉落或空背包格。
- 允许玩家提早离开、走其他路线或暂停；返回后能重新理解已发生的阶段。
- 引导与既有课表、检查、普通异象、过场、死亡和读档共享状态边界，避免互相覆盖提示或制造强制等待。
- 不自动揭示隐藏路线，不改动隐藏时刻，不强行把自主探索拉回脚本。
- 已熟悉操作的玩家可以快速完成或自然绕过教学，不反复经历不可跳过的说明。

### 4.4 验收

- 新档通过正常交互能完成整段调查；中途退出／继续后，线索与阶段一致。
- 完成者能说明至少一条发现及下一步行动的理由；观察员提供的帮助单独记录。
- 对卡点分类：没看见物件、不懂操作、不理解信息、忘记线索、方向不清、风险无法判断，分别处理。
- 触屏与键鼠都能完成；入门阶段不依赖调试功能、外部 Wiki 或精确站位技巧。

## 5. G2：调查笔记、证据与路线进度

### 5.1 内容结构

在现有笔记基础上组织以下内容，只显示玩家实际获得的信息：

| 内容 | 表达方式 | 更新条件 |
| --- | --- | --- |
| 已观察到的事实 | 简短原文、来源地点或事件；允许重读具体课堂提醒。 | 实际阅读、观察或完成相应互动。 |
| 当前推测 | 玩家根据已有证据形成的办法，明确与已验证事实区分。 | 获得足够相关线索；不按后台全局答案提前展开。 |
| 已验证结果 | 哪一步奏效、哪条尝试被否定、为什么还不能继续。 | 实际交互结果，而非仅靠接近地点。 |
| 路线进展 | 已完成部分、明确缺失的条件、可以再调查的地点。 | 由真实剧情与物品状态推导；不提前列出未知路线的完整清单。 |
| 最近发现 | 将刚得到的重要信息集中展示，便于中断后恢复思路。 | 关键发现发生时，去重记录。 |

### 5.2 实施顺序

1. 梳理课堂、环境物件、设施、路线交互和死亡记忆的线索来源，建立稳定内容 ID。
2. 将课堂具体提醒记录为可复读内容，先解决字幕消失后找不到信息的问题。
3. 为试点路线接入事实、推测与进度，随后扩展其他普通路线。
4. 补来源地点、最近发现和必要的检索；只有信息量需要时才增加分类层级。
5. 处理旧档与存档恢复，验证重复交互不会重复领奖、重复记同一条或错误推进阶段。

### 5.3 记忆规则与数据边界

- 当前 `hasClue()` 与线索获得日、笔记本和笔有关。具体线索复读沿用现有可见性规则；若要改变跨日遗忘，应作为独立设计选择记录，不在界面重排中悄然取消笔记本和笔的用途。
- 路线真实进度与可见记忆分开：忘记一条文字不回退已经完成的装置、解锁或数据操作。
- 对已拥有关键状态但缺少新线索字段的旧档，只补能够从存档证明的发现。无法证明的内容不自动解锁，也不堵住已有路线。
- 本局证据、跨局死亡经验和设置分别存放，避免重开后自动知道未发现的路线。
- 对同一地点不同楼层、同一效果对应不同死因，使用足够具体的来源标识。

### 5.4 验收

学到的具体课堂规则能按记忆条件再次查看；路线进度和实际交互一致；读档、跨天、丢失记忆道具和重开行为可解释；没有隐藏内容泄漏。玩家暂停一段时间返回后，能够借笔记恢复当前调查思路。

## 6. G3：让路线依赖观察、准备与局部操作

### 6.1 车库试点

保留车库搜索、怪物、灯光与后续驾驶流程，给玩家增加缩小搜索范围的办法。

- 原型候选：钥匙牌号的一部分、停车区记录、车辆外观特征，先选择能够与现有模型和交互配合的一到两种。
- 正确车辆与线索指向由同一份本局数据产生，并随存档恢复，避免线索和答案各自随机。
- 观察充分的玩家可以排除一部分车辆；仍需进入危险区域并完成真实交互，不能通过手册直接跳过搜索。
- 试过的车辆与排除依据能够辨认，降低忘记尝试结果造成的重复。
- 无某一特定随机天赋也能推进；错误判断应有可解释反馈，关键线索遗漏后允许回查。

**验收：** 比较有无有效观察时的尝试数量、准备行为、总耗时和压力感。保留已确认的搜索与威胁体验，不用不可操作的等待凑流程长度。正常收集、危险应对和驾驶必须完整走通。

### 6.2 实验楼与传送门

沿用日记、指定楼层图纸、材料和基座的已有结构，在不同地点增加具有差异的局部操作。可以从现有实验设施中选择观察记录、辨认组件、比较现象或简单操作组合；具体题面先做原型，再决定正式内容。

- 每处挑战提供本地可获得的必要信息，不要求外部攻略或隐含专业知识。
- 让物品和先前线索改变操作方式；保持必要材料可获得、满包可处理、失败可恢复。
- 保留已有图纸分布和路线状态兼容；新挑战不能把已经获得图纸的旧档重新锁住。
- 跨楼层移动要有明确目的，完成一处后提供可理解的进展反馈。

**验收：** 玩家能区分各处任务的思考或操作，不只记得去过几个相似的教师台；不同收集顺序、满包、失败、退出和读档都能继续。

### 6.3 白名单与驾驶

白名单已经有验证题，驾驶已经有路障、路口和追兵。本计划继续打磨已有内容：

- 白名单检查题面、选项、错答原因和进度保留，使挑战符合既定难度且反馈可理解。
- 驾驶检查路牌发现距离、转向与刹车反馈、碰撞可读性，以及触屏误操作。
- 路线提示、演出和终局判定使用同一进度，不因跳过演出或读档省略必要玩法。
- 为各路线写一份短的「玩家要观察什么、准备什么、掌握什么」说明，防止扩展后操作趋同。

## 7. G4：资源、课堂与选择的收益交换

### 7.1 先建立收益表

对物品、恢复活动、课堂和可选事件，记录即时收益、后续价值、时间成本、空间风险和可替代办法。优先找出熟悉规则后始终选择同一项的情形，再用小范围原型验证。

| 切入点 | 当前基础／观察 | 可试验方向 |
| --- | --- | --- |
| 硬币 | 买饭、售货机和诱敌共享同一资源。 | 保留并强化用途提示，让当前恢复与之后避险成为可理解的取舍。 |
| 背包 | 八格容量和多种路线物品已经存在。 | 让关键用途在取得线索后可回查；验证腾格是否带来准备决策，减少因信息缺失丢掉必要物品。 |
| 课堂 | 有 SAN 恢复、短题和规则信息，同时受到同化压力约束。 | 先提高具体情报的实际用途，再评估守规矩是否能提供值得考虑的路线信息或行动机会。 |
| 时间 | 恢复、设施与日程使用游戏时间。 | 在操作前清晰说明已知的时间代价，让玩家能考虑继续探索、恢复或赶回教室。 |
| 可选事件 | 某些选项的结果只存在不同程度的损失，例如当前假正常笑值选择。 | 优先在新增可选探索中试验信息、时间与风险的交换；既定笑值规则作为基线保留。 |

### 7.2 约束与验收

- 核心生存规则保持稳定，不通过每局随机颠倒正确应对方式制造变化。
- 信息收益要能在之后的观察或行动中使用，不以无关文本充当奖励。
- 保留玩家拒绝风险的选择；不让关键路线只剩一个随机事件或单一天赋可用。
- 防止恢复、课堂或设施奖励被反复领取；核对存档、跨天、冷却与时段切换。
- 选择的价值至少在不同资源或目标情形下发生变化，玩家能够说明放弃另一项的原因。
- “一直上课”“持续探索”“按情报安排往返”等策略分别记录进度和成本。先用模拟找问题，再用真人验证；不能仅凭关掉威胁的数值推演认定某种策略最优。

## 8. G5：危险可理解，失败可学习

### 8.1 逐项审计真实致死来源

在现有威胁矩阵上补体验记录，至少包含：来源、首次可能遭遇地点、前兆、可观察信息、可采取动作、损失／死亡条件、反馈、再次尝试前需要完成的内容。

死亡效果 ID 可能被多种情境复用，复盘应根据真实威胁来源给出信息。例如不同来源都使用同一种伸手演出时，不能仅按演出名称提供另一类怪物的应对办法。

- 检查第一次遭遇是否给过注意危险和行动的机会；有意设计的高风险交互，应能从环境或已有信息判断风险。
- 审核静音、低画质、触屏和低帧率时的重要信号是否仍能感知。
- 记录多威胁、选择框、检查、电梯和驾驶之间的冲突；复用现有事件优先级与暂停规则。
- 区分缺失提示、提示没被注意、操作失败、错误理解与主动冒险，分别修正。

### 8.2 失败反馈

保留死亡演出、墓志铭和可跳过行为。补充可回查的具体原因或相关观察，信息量与玩家已见内容一致，避免一次死亡就展示整套攻略。

当前已有首日预知梦、保护物品和同类死因重复后出现的跨局提示。先审核这些反馈的覆盖与准确性，再试验是否需要更早提供部分观察；不要把现有提示全部视为缺失。

### 8.3 重试成本

将失败后到再次进入同一未掌握挑战的过程拆开记录：重新准备、重复已知路程、已知搜索、重新观察、等待和真正的挑战。

优先改善具体规则记录、已知路线辨识和冗余交互；如要增加捷径，必须结合威胁路线和地图验证。梦魇的真正死亡与删档规则继续保留。

**条件性候选：** 如果真实试玩持续显示后半程重跑掩盖了学习收益，再评估独立的练习或探索模式。模式需明确区分正式流程与练习进度、保护正式存档，并定义是否记录结局；本计划不默认把检查点重生接入现有难度。

### 8.4 验收

玩家能解释失败的主要原因，并提出下次想尝试的动作。记录重试时间构成与是否主动再试；发生稳定软锁、错误死因反馈或输入无法执行正确应对时，先修复再评估难度。

## 9. G6：室内辨路与探索成果可见

### 9.1 地图与记录

- 保留校园总图与现有室内小地图，在手册补已访问楼层的草图和当前位置，明确建筑、楼层与方位。
- 标出实际发现的楼梯、电梯、门锁、关键房间、调查点和可达连接；未发现空间不预先填满。
- 区分已查看、已搜索、仍有待取物品和已解决的目标，避免“搜过”被误读为“没有东西”。
- 从实际房间几何、连接和玩家探索状态生成信息，防止手工地图与碰撞或楼层入口不一致。
- 必须能在切图、读档和新局后保持正确；旧档缺少探索历史时采取保守补全。

### 9.2 环境辨识

为楼梯口、关键房间和重要转角设置稳定的门牌、灯具、墙面图案或摆放特征。关键区别同时使用文字、形状或结构，避免只靠颜色；低画质仍保留必要信息。

异常可以改变玩家对空间的理解，但普通辨路信息应足够可靠。回访变化和危险演出不能让必经出口永久无法辨认。

### 9.3 验收

在返回已去过的目标、寻找上下楼连接、处理满包后取回物品等任务中，记录无目的回头和找路时间。玩家应能说明自己在哪栋楼、哪一层，以及如何回到已知地点；同时不提前获知未知房间和隐藏内容。

## 10. G7：操作舒适度、画面与声音

### 10.1 操作与文字设置

1. 为鼠标捕获视角和触屏拖动视角提供分别保存的灵敏度；检查鼠标拖动备用方式是否也有合适的调整。
2. 默认值保留现有手感，提供恢复默认；限制异常输入，旧设置缺字段时正常回退。
3. 增加字幕字号，检查长文本、选项和交互提示在放大后的换行与遮挡；保持已有停留时长设置。
4. 提供触屏按钮尺寸和位置调整，优先保障移动、视角、交互与暂停；含明确的布局归位入口。
5. 依据试玩需要评估反转视角等额外选项；先利用已有晃动、亮度和颗粒开关处理舒适度问题。

新增设置不得改变移动速度、碰撞、异象判定或课表。检验鼠标／触屏切换、全屏、横竖屏、失焦、软键盘、多指、输入框和面板关闭；调试窗口与悬浮球继续遵循各自输入范围，不能阻断窗口外游戏操作。

### 10.2 视听验证

现有方位声、前兆、假威胁和惊吓预算继续复用。试听重点是玩家能否利用信息，以及声音与实际空间是否一致：

- 耳机和外放下的左右、前后、远近、隔墙与楼层判断。
- 威胁前兆、脚步、广播和关键交互是否被背景声盖住。
- 安静、悬念、威胁和恢复之间是否有可感知的变化；熟悉后是否因重复失去注意力。
- 静音时关键风险是否有可用的视觉或文字信息；低 SAN、停电等效果下是否仍能识别必要道路和操作。
- 字幕、触屏按钮、死亡演出和过场是否相互遮挡；实际音量、晃动与闪光是否造成不适。

### 10.3 性能与验收

在真实手机连续运行中检查帧时间波动、触摸响应、温升后的变化、加载和切图停顿。把设置、分辨率、场景和测试时长一起记录。结合设备基线选择可达到的性能目标；不把软件 WebGL、静态截图或调试面板资源计数当作手机性能结论。

验收至少包含一条普通路线的触屏正常操作、一次完整暂停／恢复、死亡或结局演出、方向切换及长文本阅读。发现设备不足时先检查现有低档画质是否可用，并明确支持范围与剩余问题。

## 11. G8：重玩差异与叙事回报

### 11.1 会改变计划的有限变化

首局体验稳定后，在固定地图和核心规则上试验少量可读的变化：

- 某处辅助通路暂时不可用，但存在有线索的替代路径。
- 非关键补给或可选情报分布不同，影响进入危险区域前的准备。
- 两个可选目标的先后顺序有不同成本，玩家需要结合已有物品决定行程。
- 同一地点出现与已发现线索相关的后续事件，改变对它的理解。

每次只试少量变化，比较其是否改变决策，还是仅增加搜索次数。已有天赋、异象和物品随机性可以复用，不默认增加一套大型生成系统。

### 11.2 数据与公平性

- 本局变化、对应线索和已发生结果一起保存，读档保持一致。
- 核心生存规则不随机颠倒；已确认的课表、检查与隐藏触发不被变化系统覆盖。
- 必要物品、至少一条目标路线和可行退路保持可达，考虑满包、关键物品消耗与不同探索顺序。
- 先只影响可选地点与非关键连接，证明收益后再讨论更大范围。

### 11.3 叙事回报

让不同普通路线对学校、身份或逃离代价提供互补信息；线索应在过程中出现，结局对先前观察作出回应。可用少量反复出现的人、物件或事件建立记忆点，不以完整 NPC 对话系统为前提。

隐藏内容保持独立保密边界，普通路线的叙事完整性不依赖发现隐藏结局。记录玩家在结局前后的理解，验证额外文本是否形成联系，而不只增加阅读量。

**验收：** 重玩者能描述这次为何改变准备或行程，以及获得了哪条新的理解；验证结果必须来自实际游玩，不能仅以随机种类或结局数量证明重玩价值。

## 12. G9：真人试玩、自然长局与真实设备验证

### 12.1 三种证据分别记录

| 证据 | 能说明什么 | 不能替代什么 |
| --- | --- | --- |
| 自动化、固定输入和策略推演 | 状态正确性、可达性、重复结算、输入边界与规则数值。 | 陌生玩家是否理解、害怕、无聊或愿意继续。 |
| 真人自然游玩 | 决策、理解、探索路径、挫败感与重试意愿。 | 未覆盖设备上的帧率、触控和实际听感。 |
| 真实设备检查 | 对应硬件、浏览器和设置下的性能、输入、音画效果。 | 未参与者的普遍偏好或全平台质量。 |

### 12.2 基线与首轮盲玩

首轮建议邀请 5–8 名不熟悉项目的玩家，覆盖键鼠和触屏。人数是发现问题的试验建议，不是统计显著性的承诺；必须记录实际人数、设备与完成范围。

1. 先在基线版本记录首局关键卡点，再用试点版本观察同类任务。
2. 默认不提供 Wiki、调试或路线答案；需要帮助时记录帮助发生的位置、内容和原因。
3. 以不打断惊吓和探索为原则观察，阶段结束后询问玩家下一步打算做什么、依据是什么。
4. 首次玩家用于验证引导；同一人重玩用于验证学习与变化。两种结果分开，不把熟悉带来的改善全部算作版本收益。
5. 主动退出、暂时中断、求助、死亡后不再尝试都保留为结果，不只记录通关者。

### 12.3 观察指标

| 问题 | 记录方式 |
| --- | --- |
| 多久获得第一次有意义的进展？ | 从获得控制到取得并能解释一条有效线索或完成一个路线步骤；单纯触发地点提示不自动算进展。 |
| 玩家有没有方向？ | 记录无法提出下一步行动的时段、求助内容及恢复目标的原因。 |
| 探索是否有价值？ | 记录观察、准备、尝试、返程，以及哪些发现改变了决定。 |
| 危险是否可理解？ | 死亡后复述看到的信号、尝试的动作、认为的原因和下一次办法。 |
| 重试成本是否合理？ | 记录回到未掌握挑战的时间，拆分已知路程、搜索、等待和新尝试。 |
| 是否愿意继续？ | 记录玩家是否主动再试、探索其他路线，以及原因；不由观察员催促代替意愿。 |
| 路线能否靠游戏内信息推进？ | 记录每个步骤使用的线索、遇到的阻断、所需提示与实际结局。 |
| 操作与舒适度如何？ | 记录误触、视角过快／过慢、看不清、字幕遮挡、晕动和设备状态。 |

时间同时区分真实经过时间、有效操作时间、暂停／菜单时间和游戏内时间。先收集基线，再定义改善目标；不预填通关率、留存率或满意度结果。

### 12.4 完整路线与长局

- 为改动过的普通路线安排从正常新局或真实存档出发的完整游玩，覆盖必要收集与结局操作。
- 另外记录自然跨时段／跨日的长局；单一路线快速完成不代表一天的节奏已经验证。
- 不通过调试发物品、传送、改时间、改数值或关闭威胁代替自然通路验收。条件布置可以用于专项复现，但须单独标注。
- 记录各阶段的目标、威胁、恢复、线索、物品、死亡、空闲与重复行为，找出内容过密和无事可做的具体区间。

### 12.5 真实设备

至少记录桌面设备与可获得的真实安卓手机；手机连续运行建议 20–30 分钟，覆盖竖屏／横屏、全屏、外放／耳机、切后台恢复、关键界面和高压力场景。若计划支持 iOS，另列 Safari／设备记录；没有测试的设备保持未验证。

每份记录包含构建提交、设备与浏览器、画质与分辨率、输入方式、测试场景、持续时间、帧时间／停顿、触控表现、音画反馈和可复现问题。平均帧率之外记录明显卡顿与运行后段变化。

### 12.6 记录模板

实施后的记录附在本文件末尾或链接到已有测试／试玩资料，不再拆出新的同主题计划。

| 记录字段 | 填写内容 |
| --- | --- |
| 版本与场次 | 提交、日期、基线／改进版、匿名参与者编号或设备编号。 |
| 范围与条件 | 首局／重玩／路线／专项；难度、设备、画质、声音、输入与是否求助。 |
| 事实与证据 | 玩家动作、原话、时间、截图或日志位置；与观察者解释分开。 |
| 问题归因 | 引导、信息、决策、空间、输入、性能、数值、逻辑缺陷或尚不确定。 |
| 调整与复测 | 改了什么、影响哪些既定规则、在哪个提交验证、仍有哪些限制。 |

先采用本地记录与手工观察即可；本计划不依赖服务器、账号或线上埋点。

## 13. 工程实现与兼容要求

- **玩法状态与界面分开：** 笔记、地图和提示读取真实事件结果，不由按钮点击或显示状态直接完成路线。
- **存档可迁移：** 新增线索、阶段、探索标记和本局变化接入现有 `SAVE_SCHEMA`／`RT`；缺字段合理回退。迁移不能重复发物品、重复处罚或泄漏未发现内容。
- **随机结果一致：** 正确车辆、可选变化及指向它们的证据共用状态，不通过重新打开面板或读档重抽。
- **时间口径一致：** 设施、课表、前兆、暂停与真实时间选择沿用现有分类；新引导不能把隐藏时刻显示出来。
- **不同表现保持同一玩法：** 画质、亮度、声音和输入配置不改碰撞、关键证据位置或成功条件。
- **变更有边界：** 原型按工作包分批提交，标明启用范围与回退方式；不将未验证的平衡试验一次性覆盖所有路线。
- **文档对应实际交付：** 实现后同步相关产品、操作与测试说明；Wiki 只写适合玩家公开的现行规则，历史记录保留原版本背景。

## 15. 需要通过试验收敛的设计选择

| 议题 | 初始建议 | 收敛依据 |
| --- | --- | --- |
| 首条试点路线 | 优先车库，无法形成清晰首局时先以白名单承接引导。 | 前置长度、目标清晰度、资源与挑战的连续性。 |
| 引导强度 | 环境线索与阶段记录，必要时给简短操作提示。 | 陌生玩家的卡点、求助和自主探索行为。 |
| 笔记详细程度 | 保存具体事实，区分推测，不提前列完整答案。 | 回查是否有效、是否变成机械照表执行；兼顾现有跨日记忆规则。 |
| 课堂收益 | 先增强情报用途，再评估额外行动机会或数值。 | 玩家是否因为明确收益选择留下，是否出现无风险刷取。 |
| 死亡提示时机 | 先完善来源与覆盖，再测试首次失败后的信息量。 | 失败归因、重试意愿和谜题被提前揭露的情况。 |
| 额外模式 | 只在重跑成本证据充分时评估独立练习／探索模式。 | 后半程退出原因、重复劳动比例与正式模式边界。 |
| 重玩随机性 | 先变非关键补给、辅助连接和可选情报。 | 是否改变计划、路线是否可靠、证据与存档是否一致。 |
| 性能与舒适目标 | 按真实设备基线确定，保留默认设置与恢复入口。 | 长时间帧时间、输入响应、听感与不适反馈。 |

这些议题用于记录设计取舍，不代表每项都必须增加新功能。若试验支持沿用现状，记录原因与验证范围即可；核心目标仍是提高玩家理解、决策、学习和继续游玩的意愿。
