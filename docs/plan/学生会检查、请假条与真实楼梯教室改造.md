## 2. 学生会检查：座位与免检的三态判定

### 2.1 原座位身份

建立统一只读元数据 `ClassroomLayout.ownSeat`，至少含 `{room:'teach1', classId, seatId, col, row, facing}`；所有“开局座位”“课桌线索”“讲台归属”“检查合规”从同一数据源计算。当前默认本人座位标识对应 `MY_ROOM=5`、`MY_COL=48`、`MY_ROW=6`，重排若能保留该格就保留；不在脚本各处重复硬编码 `48.5*9` 等。

`SeatState` 不再仅一个全局 `S.seated`：坐下后记录 `seatId, room, col, row`，以及是否仍保持坐姿；起身、移动、切场景、读档纠偏清除无效占座。`atMySeat()` 验证当前 `teach1`、身份一致、实际玩家位置仍在自己座位锚点可接受误差内、`S.seated` 为真，且不是强制镜头/过场虚构姿态。

`inClassroomHere()` 如仍供“窗外的楼在动”等异象判断则保留原“站在教室内”的通用含义；**只把学生会检查替换为 `atMySeat()`，不要把所有异象误改成只有坐下才可触发**。

### 2.2 座位交互按瞄准优先

统一 `InteractionQuery.pick()`：先按射线/准星角度、距离、2D 逻辑占地及视线遮挡选择**准星真正指向的单个目标**，包括 `P`、门、讲台、抽屉、教师机、楼梯入口等；同一遮挡平面内比较距离并按稳定优先级解平局。仅把座位作为**准星确实命中时的优先对象**，不再因为邻近 3×3 存在 `P` 就无条件坐下。

- 准星瞄准自己的椅子 → 提示“坐到自己的座位”，E/触屏交互坐下并精确记录身份。
- 准星瞄准门/讲台/抽屉 → 正常开门、查看移交单/搜索；附近有座位不能抢操作。
- 准星瞄准其他可交互座椅 → 如允许坐下，记录“非本人座位”，绝不可获得检查合规；首版保留现有 `P` 交互范围，不强行给全部普通桌椅增加坐下功能。
- 同一个 `pick()` 结果同时提供 HUD 文案与 E 交互，避免显示“开门”却执行“坐下”。邻近多个道具、侧身、近距离与手机触屏均需覆盖。
- 坐姿朝向采用新的教室正面（计划为西向）；不硬编码原 `S.ang=-π/2`。

### 2.3 检查生命周期

按当前计划时刻调度，不改日程。实际 `Inspection.start()` 时分三态：

1. `excused`：此刻 `onLeave()` 为真；记录该场已免检，不创建惩罚型黑影，不要求玩家回教室、不封锁工具、不评估移动或视线；该场不加减 SAN/违规/同化，不奖励，不自动调用 `SchoolDay.grant(true)`；匹配的登记责任结算为 `excused`，不调用 `PatrolWorld.registeredAbsence()`。显示“请假有效，本次检查已免检”。
2. `present` 候选：开始时 `atMySeat()` 为真。8 运行秒内持续核验，任何离座或离开原教室都将本场标为 `absent`；原移动每秒 +2 违规、注视每秒 −2 SAN 仍照常作用。原地转头不视作离座，但注视仍受罚。
3. `absent`：开始时不是自己座位，或之后离座；结束时原缺席数值 SAN −8、违规 +10、同化 −3。即使最后才坐下也不能“补签”。

`present` 最终用原合规数值 SAN −3、违规 −8、同化 +3，合规且第 2 天起可走原自动续签；第一天仍禁自动登记。不在检查中临时把 `S.seated=true` 当作成功条件，必须使用真正占座来源。

对所有状态固定一个检查 ID（`day:slot`）与幂等结算标记。提前广播和后续调查中的“回教室”提示改为“回自己的座位”；`Inspection.cancel/stale()` 仍不处罚，旧未完成责任按现有规则顺延。

### 2.4 请假豁免与已登记责任

`AttendanceDuty` 的三态/四态转换：

```text
pending → fulfilled（坐在自己座位，检查完成）
        → absent（无假条且不合规，检查完成）
        → excused（该场检查开始时假条有效）
        → pending@下一场（检查因系统原因取消、顺延）
```

已登记的责任遇到 `excused` **视为本次合理免检并完成**，不可留下“下次迟延追罚”的悬挂承诺；但免检没有成功出勤奖励，也不产生一张新的外出登记。下一次检查需要下一次新的许可责任；保留未到期假条自己的普通豁免。

旧档 `AttendanceDuty.state` 里没有 `excused` 时按旧规则读；新增 `processed[key]='excused'` 的加载校验。其他来源的永久追踪不会因为使用假条消失；既有 `PAT.permanent` 不从已经处理的缺席记录重新生成。若本场检查原本已经完成、当时无假条，之后补用假条**不能追溯撤销处罚**。

新成就、积分与录像事实须区分三个结果，扩充 `gameFact('inspection',{result:'present'|'absent'|'excused',compliant,excused,day,slot})`：免检为中性积分，不可伪装 `present` 获取奖励，也不能伪装 `absent` 扣分；旧事件结构可迁移或兼容，历史记录不篡改。

## 3. 请假条：180 游戏分钟

`LEAVE_MIN=180`，权威时间继续用连续 `gameClock()`；不改成真实 3 小时，不用暂停/离线补时；一次消费，背包满违规封锁仍有效，已在请假中重复点击不消耗也不叠加。

普通违规、普通巡察免疫保持当前定义；**异常主动罚违规、学生会检查现在另行免疫**，但假条仍不解除永久追踪、不撤回无线破解暴露的已上报位置、不阻止办公室／网络中心报警调查。对已开始的直接追逐是否立即清除依沿用原 `PatrolWorld.hunting/exempt` 规则，不添加新重置。

`RT.leaveUntil` 继续绝对游戏分钟保存。正常存读档保持原有效期。旧档若此前已使用两小时假条，**不自动延长**：避免读档重复领收益；未来使用新假条获得 180 分钟。若希望所有旧激活假条补满一小时，应另立迁移需求，当前不默认。

HUD 改为“请假中 · 剩余 N 游戏分钟”，检查预告期间额外说明“本次免检”；检查结束给简短免检通知，避免玩家以为系统漏触发。更新 `core.js` 道具介绍、手册、Wiki 和测试断言。

## 4. 士力架：不耗体力 + 1.5 倍速度

### 4.1 数值与适用场景

| 参数 | 当前 | 新版 |
| --- | ---: | ---: |
| 效果时长 | 30 运行秒 | 30 运行秒（不变） |
| 普通步行 | 21 内部单位/秒 | **31.5** |
| 按住跑步 | 36.4 内部单位/秒 | **54.6** |
| 奔跑体力 | −17/秒 | **0**（效果期间） |
| 跑空体力限制 | 可继续跑（已有） | 保留 |
| 非奔跑时体力恢复 | +11/秒 | 保留 |

倍率仅应用于角色输入驱动的**实际地面/楼梯**位移，不应用于汽车速度、电梯移动、巡察者、剧情镜头或自动转场。保留模拟摇杆强度、斜向归一化及碰撞步进，防止增速导致穿墙。镜头步频和足音应按照实际移动速度适配，不显著放大眩晕或音量。

### 4.2 时间与恢复

`S.snackT` 更新应挪到**统一模拟效果步骤**，而非只在 `updatePlayer` 移动步骤，保证驾驶、电梯、正常终端、站立、躲柜时都正常消耗 30 个有效运行秒；暂停、CG、离线冻结。单步越过 `snackT=0` 时按边界分段，避免多给一帧速度；旧存档剩余时间正常加载且钳在 `[0,30]`。

原士力架再次使用沿用现有覆盖规则，不因 150% 速度附带无限叠加；每帧/每次输入仅乘一次。HUD 用金色时长条保持，说明新移速效果。自动录像与速通不改变自己的时间口径。

| 37..43 | `(38,15)` | `(42,15)` |
| 45..51 | `(46,15)` | `(50,15)` |

上表是**建议网格实施坐标，需经过门扇扫掠/碰撞与教室内动线验证才定为最终落点**；两个门各自有独立 `OPENDOORS` key，不再用相邻双格门判定，也不允许开前门顺带打开后门。前后门的名称由离黑板近/远决定，不按画面左右随意称呼。

为了让两扇朝走廊开的门真正成为*教室侧门*，将**黑板/教师讲授方向改为西向**：教师板位于教室西侧隔墙，讲台/教师桌靠前侧；学生桌椅朝西，背靠东，重排为相应横向座位行列，保留通往前后门的连续净空过道。窗、黑板报、空调、投影机、灯具、钟、课程表、标语、消防装置和课桌上道具随方向修正。若个别房间布局受宽度限制，允许在**内部**缩减椅子密度、腾出中/边过道，不外扩建筑、不改成两排三间。

本人初始教室仍为 `teach1`，逻辑所在教室仍是第六间；尽量保留 `MY_COL=48,MY_ROW=6`，但**以唯一元数据而非硬编码坐标为准**。不把其他楼层的对应 `P` 误当本人座位；若需要保留旧剧情可交互座位，只标注非本人，不给登记/检查收益。

### 6.2 衍生影响

- `map.js:teachFloor` 更新网格、单门及家具；`content/room-recipe.js:classroomExtras` 与 `model/room.js` 更新黑板材质朝向、教室门牌与内装；`content/furniture-recipe.js` 更新教师讲台、课桌/椅子旋转，不能只修改贴图。
- `Investigation.podium()` 目前按“`T` 在座位行数之前”推测原教室讲台；旋转后必须查 `ClassroomLayout` 的归属。`Investigation.deskAvailable()` 与 `opening.js` 当前依赖旧坐标，应统一引用元数据。
- 开场、前情提要、教室内 CG、课桌异象、黑板文字、教师模型、同学朝向、摄像机、离座提醒与楼层草图逐一对齐。房间号仍保持原标识，调查、结局、日程逻辑不挪到别楼。
- 双门须可分别开、分别碰撞、可作为巡察路径与普通遮挡；同学高违规时可堵门逻辑需要明确作用于**被围堵的实际那一扇门**，不能全教室所有门无条件同时封死。
- 开门后的模型更新只重建对应单门叶，保持已有门限转动与真实碰撞代理；出入口的交互方向和朝向在走廊和教室两侧均正确。

## 7. 实际可走楼梯：实现架构

### 7.1 覆盖

| 建筑／场景 | 范围 | 说明 |
| --- | --- | --- |
| 教学楼 | 1F—5F 两处楼梯；5F→6F 天台 | 不再交互选层；保留双楼梯间与天台出口 |
| 行政楼 | 1F—5F | 楼梯段与各层办公室走廊相连 |
| 实验楼 | 1F—5F | 机房楼层和其他实验室层不绕过原房门/网络中心锁 |
| 北宿舍、南宿舍 | 各 1F—3F | 两栋独立，互不串楼 |
| 车库 | 从当前车库楼梯到校园室外 | 根据现有车库与地坪实际高度差建造可行走梯段，不额外发明可进入新楼层 |
| 钟楼 | 现有真实旋梯 | **保持原样**，只复用其“按高度碰撞、相机跟随、存档高度”思想 |

### 7.2 物理与场景

独立 `StairWorld` 权威模块，`content/stairwell-layout.js` 用纯数据描述每座楼梯井的坐标、入口、各层楼面高度与连续梯段；配套独立楼梯碰撞和建模实现。每层建议采用**两跑梯 + 中间平台 + 转向平台**，台阶、扶手、平台、地板开洞和楼层出口在同一高度系统里，不复用原只有局部 1.3m 的装饰台阶冒充全程。

设计需满足：

- 走进楼梯、上/下台阶、经过中间平台、走出目标层都靠 WASD／触屏移动，无“上楼/下楼”选项、无整层画面黑屏或镜头跳高。
- **连续可见的楼梯段和相邻平台**：即使底层引擎仍按房间分块渲染，也必须实现楼梯井独立连续建模与门口无闪烁切换；换楼时镜头 `y` 不重置。每一刻均有合法站立面，不能通过墙、地板或台阶底板。
- 高度函数 `heightAt(stairId,segment,progress)` 给玩家物理脚高、镜头、投射声源和巡察者统一查询；每层楼面标高从真实建筑模型推导，避免 `WALLH` 与立面层高不一致。
- 精确处理下行、回头、停在平台、斜向贴栏杆、不同运行帧率、冲刺速度 1.5 倍和手游摇杆；不允许通过超大步长跨越封闭踏步或跌入未建模的空层。
- 逻辑碰撞数据来自统一几何配方，在无 THREE/GLR/Assets 条件下也能计算；更新 `isSolidCh` 不能把所有 `S` 一刀切放通。楼梯井实体宽度要为完整两跑梯重新预留，而不是沿用当前两格 `S` 的尺寸。
- 当前建筑每层 `R.id` 仍作为普通楼层标识；跨层楼梯可由独立 `stair:<building>:<shaft>` 场景/子区域承担，抵达楼层平台时无缝注册进对应 `R`。进入/离开房间仍发正确 `leaveRoom/enterRoom` 事实，切层只在**确实越过实际楼层门槛**发生，避免在平台附近反复触发。
- 背景日历、真实运行秒、体力、SAN、遭遇与音效持续推进；楼梯中存档保存楼梯 ID、梯段编号、局部坐标、连续高度、朝向与目标楼层等，读档恢复到同一踏步，不给免费跨楼。

### 7.3 与其他系统的联动

1. **巡察者**：当前已改连续步行（`speed×dt`），不能再按 2 秒抽象穿越楼层；为它提供可走的楼梯中心线/宽度、安全落点与同一高度系统，真实追击可上下坡、不能隔层抓人。行政办公室和网络中心报警只提供原区域通知，不因楼梯改变扩大感知。
2. **固定巡逻路线**：更新 `PatrolNav.graph` 的跨层连接和权重、导航/几何缓存，重新执行 `tools/patrol_geometry.py`、`tools/patrol_route.py` 生成固定路线与报告；覆盖完整性重新测量，**不得直接继承旧 68/68、旧 28 分钟实跑作为新实现证据**。
3. **检查**：楼梯里绝不是“坐在原座位”，仍可依据是否有有效假条决定免检；被检查前应有足够返程提示，若新增导航长度令 60 秒不够，应记录平衡风险，不能悄悄延迟所有检查。
4. **电梯与特殊空间**：保持电梯选层、错误电梯与虚空迷宫；普通楼梯不得误触发虚空维度或代替电梯剧情。车库出口和校园室外高度一致；不会因切换楼梯破坏驾驶或楼层间连廊。
5. **声画表现**：楼梯脚步使用现有 `step.stair` 与环境声，按真实层高控制声源方向；地图和定位应用在梯段上显示正确建筑/楼层/楼梯间，不泄露精确巡察位置；不同画质、暂停恢复不能改变导航权威。

## 8. 存档与迁移

| 旧状态 | 迁移方案 |
| --- | --- |
| 已坐下 `S.seated=true`，无 `seatId` | 若位置是旧 `teach1` 玩家座位并在阈值内，映射成新座位 ID；否则取消坐姿，安全落在同房间最近合法点；不凭真值远程判自己就座 |
| 地图/场景旧格坐标 | 保留楼名及朝向，若恰落旧门框/新家具/平台，确定性搜索最近合法落点；失败提供安全回退与提示，不放入锁门背后 |
| 旧 `OPENDOORS` 双格宽门 | 映射到同班新前后**单门**的独立状态；默认保持旧门已开的通行资格，不能产生读档后卡死；记录一次迁移，之后不重复复制 |
| 旧楼梯 `S` 邻近落点 | 转到对应楼层的真实楼梯**入口平台**，而非中途随机踏步；非楼梯的楼层位置尽量保持 |
| 普通存档中已使用请假条 | 保存的 `leaveUntil` 不自动增加 60 分钟，新使用一律 180 游戏分钟；已结算旧检查不追补、更不撤回 |
| 旧天赋 `stomach` | 映射 `none` 并注明失去已删除能力；不随机重抽，也不改变其他状态 |
| 旧进行中的检查 | 当前检查已开始者沿快照语义恢复；无有效自己座位标识不补合规；用户若旧档有有效假条，则在恢复时显式按本次新规则判定且防二次结算 |
| `AttendanceDuty` | 增加 `excused` 状态的读取/验证；原 `fulfilled/absent` 保留，曾结算事件不重新结算永久追踪 |
| 士力架 `S.snackT` | 保留剩余真实秒，范围不超 30；读档不重置倍率或重新赠道具 |
| 成就、积分与速通 | 不删除历史记录；新的检查 `excused` 按中性记录；规则版本隔离新旧速通成绩，保留历史资料 |

所有字段写入仍遵守 `GameModules.persistent`/`SaveData.prepare`，纯加载不触发物品消费、检查奖励或事件重新发报；Mod 独立数据按现有兼容规则保留。

建议新增或复用的责任：`game3d/js/domain/classroom-layout.js`（教室锚点/朝向/门与座位身份）、`game3d/js/domain/stairwell-geometry.js`（连续高度和合法表面）、`game3d/js/modules/stairwell/`（场景切换和局部控制）、`game3d/js/content/stairwell-recipe.js`（模型与碰撞同源）。文件路径是实施建议，可按现有边界规范调整，但**不能同时在多个模块维护彼此矛盾的座位坐标或楼梯高度**。

工程工具：先登记 `game3d/manifest.js`，必要时导出共享碰撞代理，执行 `node tools/link_modules.cjs --write` 与 `python tools/check_modules.py`，再执行相关单测、浏览器自动化和完整回归。模型与玩法改动应做对应真实位置的穿模检查，并按仓库约定提供 `pictures/<主题>/` 截图索引，更新产品对齐、Wiki（仅公开规则）和计划索引；**源码改动应新开 PR 审查，不因这份计划直接推 main。**

## 10. 验收矩阵

### 10.1 检查与假条

- [ ] `teach1` 自己座位 8 秒均坐稳 → 合规；在 `teach2` 或 `teach1` 其他座位 → 缺席。
- [ ] 检查开始时未坐 → 即使后来坐下也缺席；开始时坐着但中途 E 起身／离开 → 缺席；单纯转头不算离座，但注视黑影照扣 SAN。
- [ ] 瞄准 P 才坐，瞄准门/讲台/桌子仍执行对应操作；键鼠、方向键、触屏方向目标一致。
- [ ] 请假条在检查开始前有效 → 任何地点都免 SAN/违规/同化、现场移动/注视惩罚、永久追踪与签到责任；不领取奖励/自动续签。
- [ ] 假条开始后中途到期本场仍免；检查开始后才使用不追溯；曾经缺席已结算不能靠新假条撤销。
- [ ] 已有讲台责任在免检场次结为 `excused` 且不重放；两场检查、跨夜、系统延期/取消、预知梦/药丸救回/读档均无双重结算。
- [ ] 第一日仍不能手动或自动登记，但可用请假条；第二日起登记责任照旧；无线报警/永久追踪不被假条删除。

### 10.2 道具、天赋

- [ ] 新假条 180 游戏分钟，不是 180 现实分钟；场景切换和纯校历跳时按实际游戏时钟到期，正常读档保留绝对截止时间。
- [ ] 违规记满不能用，降到 60 以下恢复；请假状态重复用不消耗；旧已激活假条不自动延长。
- [ ] 30 运行秒内走/跑分别 31.5/54.6、跑步不掉体力；暂停冻结、躲柜/梯间/电梯/终端/驾驶正常倒计时；斜走/触屏/高速墙角不穿模。
- [ ] 旧 `stomach` 档迁移到无天赋且不重新抽；新局和随机池中没有铁胃；盛宴阈值回 9 秒、普通吃饭恢复基数回 18。

### 10.3 教室与楼梯

- [ ] 1—5F 每层六间教室各有前后两扇**独立单门**，从同层走廊均可到达；门开关互不连带，门框/黑板/灯具/座位/柜子不穿模。
- [ ] 原教室本人座位、讲台移交单、课桌停车记录、开场 CG、课桌异象与课程任务仍可按真实交互到达。
- [ ] 所有指定楼梯可由玩家用移动连续登上/走下，不用选择菜单；中间平台转身、楼层交接时无黑屏、无坐标/高度跳跃。
- [ ] 在半阶、平台和楼层门槛上保存/读档安全；动态碰撞按高度处理；大步长士力架冲刺也不会穿过护栏或跨楼板。
- [ ] 宿舍之间不串楼、车库出口与室外合法连接、教学楼上天台保留、钟楼旋梯不回退；电梯、连廊、门户结局不受损。
- [ ] 巡察者沿真实楼梯跨楼，连续步行速度与几何路径一致；楼层间不可隔板抓捕；出楼/入楼、特殊区域报警及无线快照仍正常。
- [ ] 重新生成固定巡逻线路与覆盖报告，离屏/可见/不同画质轨迹一致，真机不出现持续重规划卡顿。
- [ ] 两种低画质与高画质、桌面键鼠和 Android 触屏下都能读懂楼梯方向与前后门门牌；声画不影响物理判定。

### 10.4 综合与验收证据

- [ ] 无浏览器纯规则、模块边界、全校几何、座位和楼梯合法图、存档迁移测试通过。
- [ ] 浏览器实际操作完整经历：第 1 天进自己教室坐下→检查；第 2 天请假免检→新登记→正常检查；士力架跑楼梯→高违规堵门→仍可换另一个门/其他合法办法；夜间与追击。
- [ ] 原四条公开结局、出入口、网安终端、成就/积分、速通记录各至少一条集成回归；无隐藏剧情的公开泄露。
- [ ] 有真实截图及碰撞报告，记录全量测试与最终指纹；未做真人盲玩或实体手机验收时明确列为待完成。
