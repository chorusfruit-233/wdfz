# 计划｜全死亡方式与结局 CG 重制、隐藏触发时刻校准

> 状态：**待实施**（本文件是实施计划，不代表代码、CG 与计时修正已经完成）  
> 建档：2026-10-30  
> 适用：**3D 版本**；保留现有玩法主线与结局判定语义。  
> 保密级别：**内部开发计划，含隐藏彩蛋剧透；严禁把本计划中的隐藏内容、时间或异常同步到玩家 Wiki**。  
> 执行优先级：用户当轮指令 > `CLAUDE.md` 中的彩蛋保密最高规则 > 本计划；用户本轮未授权时，避免顺手执行无关计划。

## 1. 总目标和边界

- **全面优化并重写所有死亡方式的游戏内 CG / 3D 演出**，不满足于仅改变屏幕颜色、闪黑或重复简单模型；每一种实际存在的死亡类型都应有符合死因的镜头、场景变化、动作、光影及声音，保持恐怖感、因果和可读性。
- **全面重制所有现有结局的实时 CG 动画**，使剧情动作、镜头运动、环境与人物表现完整，并保留不同结局的差异。现有可见结局与隐藏结局都属于重制范围，但隐藏内容只在内部代码、测试和受控开发文档出现。
- **将隐藏《先辈》结局的正确触发时刻校准为游戏内 11:45:14**；判定、相关计时体验、游戏内提示、存档边界与自动测试都必须一致，禁止只修改显示文本。
- **玩家 Wiki 仅公开普通内容**。当前只删除 Wiki 中《先辈》隐藏结局的攻略及直接泄露其触发窗口的提示；不删除或误改其他普通结局、已公开的正常异常与玩法信息。此后任何新增的彩蛋结局、彩蛋触发时间或彩蛋异常都一律不得进入 Wiki（包括名单、数字总数、目录、脚注、搜索关键词、HTML 注释与其他间接线索）。
- 不因 CG 重制改变普通死亡救命机制、结局获得状态、假结局回归、存档清理、操作方式、时间倍率及难度规则；任何确需调整的行为需单独明确记录并经用户指令允许。

## 2. 实施前的盘点与基线

1. 从 `game3d/js/story.js` 的 `kill()`、`DEATH_MESSAGES`、`DFX_EPI`、各处 `kill(..., fx)` 调用以及 `game3d/js/dev.js` 的 `DEV_DEATH` 整理 **全部死亡类型与真实触发来源**。当前调试面板列有约 28 个效果条目，不能把面板枚举误当作完整覆盖：还需搜索所有实际死亡调用，列明别名、兜底、不可达类型和同一种效果被多处复用的情形。
2. 对照 `game3d/js/fx/anomaly-fx.js` 的 `deathFX()` 与 `anfxUpdate()`、`game3d/js/engine/scene.js` 镜头、`game3d/js/audio.js` 的 `SFX.deathFx()`、`game3d/js/dev.js` 的预览能力，记录每项当前画面与问题：没有因果动作、素材不清晰、遮挡、动作突变、过曝、纯黑屏、重复套路、视角晕动、音画不合拍、资源泄漏等。
3. 对照 `game3d/js/cutscene.js` 的 `CUT_DEF`、`playCut/cutTick/cutFinish/cutSkip` 及 `triggerEnding()`，盘点当前五条结局路线：`car`（闸门）、`face`（白名单）、`trash`（第三个桶）、`beast`（隐藏先辈）、`portal`（门）。仅作为**内部覆盖清单**；不可照搬到公开 Wiki。
4. 生成内部映射表：**触发事件 → 死亡类型／结局 ID → 演出脚本 → 音效 → 特效资源 → 跳过／清理行为 → 测试用例**。逐项确认覆盖，严禁漏做、把不同死因全部套一个 CG 或以静态图顶替实际演出。
5. 保存改造前的截图／视频与性能基线，至少包括低画质安卓触屏环境及桌面浏览器。测试证据按原仓库规则存入 `pictures/<轮次或主题>/` 并更新 `pictures/README.md`。

## 3. 死亡 CG 全面重写标准

### 3.1 统一的演出结构

每个死亡类型分别设计至少四段连续阶段：**前兆（危险可感知）→ 接触／失控（明确死因）→ 临终视角（有心理压迫与环境反馈）→ 收束（接死亡界面）**。节奏可不同，但必须能看懂发生了什么、由什么造成死亡。

- **镜头**：优先沿用第一人称空间逻辑，设置稳定的关键帧、视线目标、运动曲线和镜头惯性；碰撞或强制转头符合场景，避免穿墙、穿模和瞬移；支持降低晃动、闪光的设置。
- **人物／怪物／环境**：提供与死因匹配的动作和几何反馈，例如被抓、坠落、窒息、围观、镜像、长颈、钟声、雨水、冰冻、纸面姓名、灯光异常等。尽量复用现有模型与材质，但允许为独特叙事制作专用 3D 资源、动画轨和粒子。
- **光与声音**：声音必须拥有明确的方位、距离和事件时机；环境声变化、低频与短暂静音配合镜头，在实机上检验音量与延迟；不要用连续强烈闪烁取代恐怖氛围。
- **时序**：定义时长、触发点、每阶段停留和字幕出现／退出时机；帧率波动后仍按时间轴正确推进，不得依赖固定帧数。
- **统一接口**：把资源创建、预览、实际死亡、跳过／结束与销毁边界梳理清楚；支持调试面板逐项预览，不污染真实玩家状态。未注册类型给合理兜底，但真实可触发的类型必须拥有对应定制演出。
- **可访问性**：适配手机／PC、横屏、低亮度、五档画质；遵守减弱镜头晃动、降低闪光相关选项，字幕在小屏可读，避免持续致眩的频闪。
- **原有判定保留**：先走救命道具、无敌、预知梦等逻辑，再进入实际死亡；保留原有保存／删除与恢复流程。禁止为了演出再次调用 `kill()`、重复扣数值、重复记录死亡或污染结局解锁。

### 3.2 逐类型制作清单（每项均需单独验收）

按调试列表起步、再由真实 `kill` 调用补齐：`vignette` 黑影、`floor` 地板、`grip` 抓握、`neck` 长颈、`shadow` 影子、`swarm` 蛾群、`drown` 雨、`water` 水、`freeze` 冰冻、`gaze` 回头、`stare` 围观、`voice` 广播、`bell` 钟声、`follow` 跟随、`shatter` 碎裂、`deep` 深坑、`ring` 仪式、`names` 名单、`chalk` 黑板、`loop` 走廊、`twin` 双生、`lamps` 灯、`slit` 缝隙、`squeeze` 挤墙、`face` 面孔、`wall` 墙、`laugh` 笑、`mirror` 镜面。

每项建立独立验收记录，包含：触发情境、三到五个镜头节拍、关键动作／音效、具体改动文件、低画质呈现、跳过与释放、回归通过情况。若实际游戏还有其他死亡效果，必须纳入，不以本表为上限。

## 4. 结局 CG 全面重制

内部五条路线全部制作差异化分镜，不改变原结局的因果和奖章／存档语义：

| 内部 ID | 演出重制方向 | 必须验收的叙事点 |
| --- | --- | --- |
| `car` | 车内视角、点火与车窗反射、逐渐远离的校门、后视镜中的学校异变、声场变化 | 车辆真的行驶、镜头与景物视差一致、开车路线不会漏触发或重复 |
| `face` | 西小门闸机解除、跨越门线后回望、校园内不自然聚集的目送者 | 距离层次、人数渐显、凝视节奏、无穿墙和失真 |
| `trash` | 第一人称进入桶内、桶盖开合、封闭空间撞击与敲击、压抑的断续光线 | 假结局可醒来、继续状态不丢失、出桶和跳过能正常恢复 |
| `beast` | 厕所隔间声响与开门、旧校服角色的奔跑轨迹、追随视角、环境色彩变化 | 隐藏结局只在正确内部触发时演出；不得借 CG 更新向 Wiki 泄露 |
| `portal` | 实验装置充能、光圈稳定成形、材质／光线反应、进入并转场 | 使用材料与场景一致、白场转场不过曝、完成后正确显示真结局 |

- 采用可编辑的**实时 3D CG 分镜／时间轴**，不简单替换成静态图片或重复全屏滤镜；逐段整理模型、动画、相机、灯光、音效、过场文字、字幕与完成回调。
- 保持 `CUT.enabled=false` 的测试路径；点击／空格／回车／Esc 仍能可靠跳过，跳过与正常播放须走同一完成逻辑，完成回调只触发一次。
- 切镜结束释放临时 `THREE` 对象、材质、纹理和粒子，恢复雾、曝光、`worldNorm`、输入、音效、镜头与 UI 状态；连播、跳过、重开、存读档均不得遗留效果。

## 5. 隐藏结局《先辈》的精确时间修正

**目标时刻：游戏内 11:45:14，精确到秒。** 本计划把“触发时刻”定义为以 `11:45:14.000` 为起点、到 `11:45:15.000` 前的**一个游戏秒窗口**（前闭后开），而非原先 11:45:00–11:45:10 的十秒区间。除非用户另有明确指令，不扩大为十秒容错、不允许 11:45:13 或 11:45:15 触发。

1. 修改 `game3d/js/core.js` 中 `BEAST_T0`、`BEAST_T1`、`BEAST_RATE` 与 `rateAt()` 的窗口定义，避免分钟浮点精度影响；重点核实真实时间减速体验。新窗口只有一个游戏秒，**不能原样保留“10 个游戏秒约 15 真实秒”的换算关系并误称新窗口仍有 15 秒**。如需维持约 15 秒真实操作机会，需对应重设流速；慢速前兆的范围应单独设计，且不得导致提前触发。
2. 核对 `game3d/js/systems.js` 的 `clockTick()` 分段跨窗口处理和游戏内提示；大步长推进、暂停恢复、跳时与跨天不能吞掉或重复触发窗口。
3. 核对 `game3d/js/items.js` 的 `inBeastWindow()`、丢物品逻辑及 `game3d/js/story.js` 的 `tryBeastRoute()` / `useStall()`；保留“地点／丢弃道具／后续交互”的已有必要条件，确保只有新时刻正确触发。错过不误触发；成功不重复消费。
4. 更新**游戏内**隔间刻字、对白、道具说明、秒表提示、调试项及其他包含旧时刻的**内部代码和开发文档**；禁止把新时刻、新线索写入 `wiki/`。
5. 修订 `tests/test_controls.py` 的 `test_ancestor_window_is_slowed_and_dropping_item_ends`，覆盖 `11:45:13.999`、`11:45:14.000`、`11:45:14.999`、`11:45:15.000`、普通推进跨边界、时钟准确性、失败后重试／次日、存读档及所需交互条件。
6. 补充开发记录说明由旧时间窗口迁移至新窗口的影响；存档、历史成就不应出现错误或被意外清空。

## 6. 玩家 Wiki 彩蛋保密红线（强制）

- `wiki/` 是玩家可见内容，**不得发布任何彩蛋性质的结局、时间、异常**。包括名称、触发位置、提示文本、条件、步骤、奖励、插图、动画剧透、计数暗示、隐藏链接、HTML 注释、`meta`、结构化数据和可搜索的关键词。
- 本轮仅清理 `wiki/index.html` 中《先辈》专属攻略、与之相关的旧秒级窗口提示，并把“全部结局／数量”之类会泄密的总量文案改为“公开结局”措辞；其他正常攻略原样保留。**不要从 Wiki 删除其他已公开结局，也不要因为全面同步文档而把秘密重新贴回去。**
- 后续新增彩蛋结局、隐藏时间事件、彩蛋异常时，只能更新游戏源码、内部开发文档和相关回归测试；玩家 Wiki 的同步应跳过这些条目。公开内容可以继续按事实更新。
- 建立 Wiki 静态回归测试（例如检查已知隐藏 ID、名称、秒级时间和专属地点／提示不会出现在 Wiki HTML、目录、注释、SEO 文本中），但**不要在公开的 Wiki 或用户可见错误信息中列出隐藏条目清单**。
- 与“每次更新后同步 Wiki”规则冲突时，**此保密红线优先**；未来要改变必须由用户明确指示公开具体内容。

## 7. 测试、截图与验收门槛

- **功能**：每一种可达死亡触发后都出现其专属 CG；救命效果拦截时不误播放；五条结局逐一播放并可跳过，结局解锁与存档语义保持原状；新时刻仅在正确精确边界内有效。
- **视觉**：每条路线验证分镜连续、光影与色彩符合恐怖设计原则、不出现明显穿模／摄像机穿墙／角色滑行／镜面失真；只有实际涉及建模或玩法更新时按项目规定执行穿模检查。
- **性能**：至少覆盖安卓低画质与桌面高画质，测量峰值帧时间、绘制次数、临时对象数量与结束后资源回收。若低端设备掉帧，做对象复用、LOD、粒子限额与降级路径，而不是删掉故事关键动作。
- **兼容**：横屏触屏、键鼠；保存后继续、假结局回归、预知梦、死亡救命、立即跳过、连续两次预览、切换画质、切换场景、后台恢复均正常。
- **自动化**：扩充 `tests/test_controls.py`、`tests/test_dev_panel.py` 和适用的资源／引擎测试；使用公开 Wiki 的测试验证没有隐藏线索，且正常 Wiki 链接与攻略不受损。报告通过、失败与未覆盖项。
- **交付证据**：按死亡 ID 与结局 ID 分类保留截图／短录屏索引，更新 `pictures/README.md`；同一 PR 提交代码、测试、内部开发记录、允许公开的普通 Wiki 内容及必要的文档更新。
- **验收拒绝条件**：遗漏任何实际死因、任何结局使用无关通用片段、触发时刻错一秒、隐藏内容再次出现在 Wiki、跳过后残留特效、游戏流程／存档回归失败、宣称未测试功能已通过。
