# 模块边界与迁移

本文件描述模块化接口及后续功能的接入。设计背景见[项目解耦与模块化](plan/项目解耦与模块化.md)，验证结果见[测试说明](测试说明.md)。迁移保留本地普通脚本、Three.js、现有玩法与存档格式。PR #25 的天赋规则 2、新局开场 CG、速通、死亡档案室与特殊校园日已随该 PR 合入，接法见[第 7 节](#7-pr-25-功能的接入)。PR #29 的常驻巡察与手机服务器路线见第 8 节。

## 1. 入口与依赖

本地脚本的加载清单是模块清单 `game3d/manifest.js`（PR #26 起：`index.html` 只加载注册表 `game3d/js/modules.js` 和清单，由 `GameModules.boot()` 按清单顺序同步写入普通脚本，`file://` 照样能开；见[模块化与Mod规范](模块化与Mod规范.md)）。纯规则模块在使用者前加载；`app/session.js` 在游戏系统加载完成后组合它们；`main.js` 最后启动。

| 模块 | 责任 | 依赖边界 |
| --- | --- | --- |
| `app/input-context.js` | `GamePolicy`：模式、输入归属、模拟与表现推进策略 | 只接受普通上下文数据，不读取浏览器或全局游戏对象 |
| `input.js` | 原始设备输入、`gameInputContext()`、移动与手势兼容入口 | 把浏览器事件转换成当前上下文中的操作 |
| `app/lifecycle.js` | 可取消资源作用域、失效回调保护、退出钩子与诊断 | `LifecycleCore` 可注入时钟；`Lifecycle` 负责浏览器接线 |
| `app/session.js` | 新局、继续、退出、暂停、恢复与系统清理组合 | 保留 `Game`、`freshState` 名称，避免现有 HTML 和工具调用断开 |
| `domain/player-stats.js` | `StatRules` 纯数值计算与 `PlayerStats` 写入接口 | 不读 DOM、Three.js、存储；通过状态提供函数绑定当前会话 |
| `domain/game-time.js` | 日历分段、运行秒换算与压力插值 | 不执行剧情、音画或存档副作用 |
| `domain/inventory.js` | 背包容量、数量、选中与快捷栏规则 | 数据由实例拥有，物品表现与提示由 `items.js` 适配 |
| `domain/save-data.js` | 校验、规范化、旧时钟迁移与序列化 | 不读当前游戏状态；传入房间、物品索引供校验 |
| `adapters/storage.js` | 可注入存储后端、读写失败结果与诊断 | 不决定何时存档，不删除失败操作前的原值 |
| `systems.js` | 将数值和时间规则接入实际课表、检查、跨日与剧情 | 保留 `settleSan` 等薄兼容入口和现有执行顺序 |
| `save.js` | 字段协议、存储调用和按依赖恢复系统 | `applySave` 恢复规则数据；`restoreSavePresentation` 单独重建界面／表现 |
| `engine/`、`fx/` | 场景、镜头与演出实例 | 临时镜头状态在表现层，死亡预览不写回玩家朝向／位置 |

普通脚本继续是正式交付方式。原生 ES Modules 不作为本轮硬性目标：现有静态托管、离线资源和本地页面兼容优先。没有增加 npm、CDN 或线上构建依赖。

## 2. 状态归属与兼容

| 数据 | 正常运行写入者 | 特殊入口 |
| --- | --- | --- |
| SAN、违规、同化、体力 | `PlayerStats` | 新局种子由 `app/session.js` 初始化；`save.js` 恢复数据，避免重放伤害或奖励 |
| 日历与跨日事件 | `GameTime`／`systems.js` | 新局和存档恢复；调试修改沿用独立设值语义 |
| 背包和快捷栏 | `Inventory`／`items.js` | 新局和存档恢复；保留旧物品函数作为兼容入口 |
| 位置、碰撞与姿态 | 移动、场景交接、驾驶及躲藏系统 | 渲染不再承担卡墙纠正；存档和调试定位仍校验可达位置 |
| 插值视高、视野与行走表现相位 | `VisualState.camera` | `Engine.resetCamera`／`resetSan` 在切换会话时重置 |
| 死亡演出镜头 | 演出实例和 `ANFX.view` | 真实死亡及预览使用独立视图；结束释放表现覆盖 |
| 异象、巡察、路线标志 | 现有异象注册表、巡察系统和路线系统 | 生命周期调用系统自身清理函数；读档字段表负责恢复 |

`S`、`RT`、`AN`、`PAT` 等继续是兼容数据容器，不能据此宣称全仓已经没有全局变量。此次重点是禁止跨模块直接改四项核心数值、隔离纯规则和演出，并为会话建立统一资源边界。旧系统尚未移动进 `domain/` 的部分属于应用适配层；迁移新功能时不得把 DOM 或 Three.js 依赖带进纯规则。

保留两项明确的兼容边界：同学注视条件仍通过 `ncPressureState()` 查询当前同学场景是否存在；随机视觉效果和玩法仍共用原 `Math.random()`。前者没有继续在表现更新中扣数值，后者避免本轮重构突然改变后续玩法的随机取样序列。这些不是“全部领域已独立”的证据，若后续迁移，应单独验证场景与随机行为等价。

`PlayerStats.changeSan` 默认保留步内尚未裁剪的原行为。原调用有上限或下限时显式传入 `{max:100}` 或 `{min:0}`，最终仍由 `settleSan()` 统一结算死亡。该接口不会自动再次乘天赋或校园压力倍率，避免重复修正。违规的请假／晚间豁免与检查例外仍由规则入口明确处理。

## 3. 输入与时间

`GamePolicy` 读取快照，不保留第二份游戏模式。`mode()`、`inputOwner()`、`simulationAllowed()` 与 `presentationAllowed()` 对同一上下文作出一致判定。

| 上下文 | 世界模拟 | 玩家移动 | 处理原则 |
| --- | --- | --- | --- |
| 正常游玩 | 继续 | 允许 | 课表和威胁按固定步更新 |
| 文字前情／正式过场 | 停止 | 禁止 | 正式过场优先消费跳过键，文字前情只处理自己的翻页 |
| 暂停、普通面板、电脑小游戏 | 停止 | 禁止 | 对话／画面按各自表现策略运行，小游戏有独立更新入口 |
| 手机、新服务器终端、课堂互动 | 继续 | 禁止 | 终端独占文本输入，仍能立即退出；原贪吃蛇保持暂停 |
| 调试打开、未冻结 | 继续 | 面板外允许 | 面板自己的输入被消费，拖动和冻结另外处理 |
| 调试主动冻结 | 停止 | 禁止 | 可保留显式的表现预览 |
| 异常电梯空间 | 继续 | 按原规则 | `R.noClock` 只停止校历，设备与服务器仍推进 |
| 死亡／返回菜单 | 停止正常模拟 | 禁止 | 只允许对应流程的操作与结束处理 |

模拟运行秒、日历和表现时间各司其职。PR #29 新增 `Mechanics.activePlaySeconds`：只累计已接受的模拟步；后台停止，并在可见性变化时清空累计步长，恢复后不补离线收益。普通卡顿仍遵守主循环步进上限。RTA 独立使用真实经过时间，暂停和后台照计，不能复用设备时钟；接法见第 7 节。

## 4. 生命周期接入

每个异步操作取得自己的作用域。`timeout` 在退出时取消；`guard` 在回调执行前检查该作用域是否仍有效。场景转场和会话更换会使旧回调失效，避免上一局的淡入、字幕、死亡或加载结果覆盖新局。

系统清理在应用组合层注册，清理实现仍属于系统自身。不要在退出入口直接抄写另一个系统的内部字段。反复清理需要安全；局部特效只能释放自己拥有的资源，不得销毁全局共享纹理和模型缓存。

调试诊断可读取输入当前归属、模拟是否推进及生命周期作用域。关键清理失败记录模块和会话信息，便于区分状态残留与视觉降级。

## 5. 存档协议

保留 `v:1`、`clockVersion:2` 和原存档键。`SaveData.prepare` 返回独立副本，旧时钟与冷却只迁移一次；已知字段被校验，未知扩展字段保留。加载错误发生在重置当前会话之前；存储写入失败不先删除旧存档。

恢复依次经过数据校验、会话准备、规则字段恢复、表现恢复和场景进入。保存数据不含 DOM、渲染对象、定时器句柄或函数；读档不重新执行物品使用和奖励命令。

## 6. 持续验证

```bash
python tools/check_modules.py
PYTHONPATH=tests python -m unittest test_module_boundaries test_domain_rules test_input_policy test_save_boundary test_lifecycle -v
PYTHONPATH=tests python -m unittest discover -s tests -v
```

`tools/check_modules.py` 从模块清单展开实际加载顺序，检查脚本是否实际加载、关键启动顺序、纯模块越界与直接数值写入。它是静态约束，不能证明全部运行时依赖无环，也不替代浏览器回归。新增纯领域模块自动接受边界检查；新启动依赖补到 `BEFORE` 表中。

测试应重点覆盖真实交叉流程和数据兼容。无浏览器测试验证规则；浏览器验证输入、画质、存档和演出；软件 WebGL 与触屏仿真不代替真实设备性能和真人手感验收。

## 7. PR #25 功能的接入

PR #25 合入主分支模块化时（2026-11-02），本分支新增的模块都按前面几节的边界接入，没有给它们开例外：`tools/check_modules.py` 照旧只允许 `app/session.js` 和 `save.js` 直接写四项核心数值。

| 模块 | 责任 | 接入方式 |
| --- | --- | --- |
| `talents.js` | 天赋定义源与规则版本；`Talent.begin / capability / modifier / tryPreventDeath / faceRemedy / pauseText` | 只返回能力、修正值或判定结果；数值仍由调用方经 `PlayerStats` 写入（如铁胃的吃饭基数先交给 `CampusPressure.restGain` 再 `changeSan`）。新局由 `app/session.js` 的 `freshState` 调 `Talent.begin`，选择界面确认前不碰存档 |
| `day-events.js` | 校庆 / 占课特殊日；`sanDrain()` 逐秒消耗入口 | `sanDrain(rate,dt,source)` 乘校庆倍率后调用 `PlayerStats.changeSan`，异象、巡察、危险区、漫游者的逐秒消耗都走它；校庆横幅 `DayDecor` 由生命周期钩子 `day-decor` 清理 |
| `speedrun.js` | 速通 RTA、个人最佳 | 用 `performance.now()` 计真实经过时间，暂停和切后台照计；第一次 `GamePolicy.playerAllowed` 为真（且不在过场）时起表。开速通时 `app/session.js` 调 `Dev.clearModifiers()`，把跨局保留的快跑、无敌、关读条恢复成常规状态（开关仍归 `dev.js` 管）；结算时用 `Dev.modifiersActive()` 再查一次。回菜单由钩子 `speedrun`（只处理 `menu` 边界）记放弃、清掉速通存档槽 |
| `save.js` 的 `saveSlot()` | 速通独立存档槽 | 速通局经 `GameStorage` 读写 `wdfz3d_speedrun_slot`，普通局和「继续上次」只用 `wdfz3d`；成绩另存 `wdfz3d_speedrun_v1` |
| `death-archive.js` | 死亡档案解锁与隔离回放 | 只在真实死亡演出收尾时由 `story.js` 调 `DeathArchive.notify`；保命挡下、调试预览、回放不解锁。回放时 `S.screen='replay'`，`GamePolicy` 判为非游玩，模拟不推进、不写存档；演出资源由 `anfxClear` 释放 |
| `opening.js` | 新局 3D 开场 CG 与交接 | 演出期间 `PRO.on` 挡住输入、`S.screen='cut'`，`GamePolicy.mode` 把跳过键交给正式过场（即计划 A-01 的修复）；看完和跳过都走一次 `Opening.handoff`。没演完回菜单 / 读档由钩子 `opening` 收掉，开场字幕定时器在 `intro` 作用域里 |

天赋状态（`S.talent`、`S.talentState`）由 `Talent` 负责，`S.immuneUsed` 只是 `talentState.consumed.fatalProtection` 的兼容别名；读旧档时 `Talent.normalizeSaved` 把未知或缺失的天赋读成「没有天赋」、旧存档保持规则 1。

## 8. PR #29 常驻巡察与手机网络的接入

`domain/phone-energy.js` 负责电量、任务供电时长和边界切分；`domain/campus-terminal.js` 负责游戏内虚拟文件与命令；`domain/route-graph.js` 负责图算法。它们不依赖 DOM、Three.js、浏览器存储或宿主命令执行。全校路线由生成工具用精确匹配求解，运行时读取版本化产物。

`PatrolWorld` 拥有唯一敌人的位置和策略，`PatrolNav` 使用从真实碰撞体生成的静态导航数据。`patrol.js` 保留旧调用入口、模型与储物柜交互；换场景只清模型，不销毁权威实体。渲染缓存、当前画质和玩家房间不能决定离屏可达性。新局和数据恢复的纯状态重置不写红屏等表现状态，表现恢复仍由既有入口执行。移除可选迷宫模块时，导航从原白色空间的纯地图生成墙体栅格，永久追踪与读档不引用已缺失的迷宫接口。

`Mechanics.begin(dt)` 在驾驶、电梯等提前返回之前调用一次；随后推进校历、巡察与原系统，`finally` 中的 `Mechanics.finish(dt)` 在危险／救回结算后执行停机仲裁。纯校历跳时不生成运行秒，课堂整理的完整模拟步会推进。不得在各分支再补调用一次设备计时。

`PhoneNetwork` 拥有设备与临时接线；`TerminalUI` 独立于原小游戏的 `PC.on`。终端使用文本输出，键盘事件不进入移动键状态；`visualViewport` 的尺寸和偏移决定软键盘出现时的可见窗口。关闭、断电、转场或强制事件保留输入和工作文件，但清理临时连接。手机和行政楼门禁机共同调用 `WhitelistSync.commit`，只有一份 `RT.data`。

新增存档域为 `mechanics`、`patrolWorld`、`attendanceDuty`、`phoneDevice`、`terminalPuzzle`、`termination`，通过 `GameModules.persistent` 注册。正常读档保留业务进度、断开界面和电脑连接；药丸／免疫保留新路线并解除永久追踪；预知梦重置新路线和检查责任、保留旧白名单与科技党代价。坏谜题只重置谜题域，缺失的新设备域按空电修复，不反复赠送满电；停用 Mod 的数据仍归原命名空间保存。

`cyber` 的 3D 结尾使用 `Engine` 舞台和 `Lifecycle` 作用域，广播声音、模型、纹理随演出收尾或跳过释放，不写玩家位置／朝向。公开速通规则升至版本 2，旧记录按版本隔离。详细恢复矩阵与验收范围见[对应计划](plan/巡察者常驻、手机网络系统与网安仙人.md)。
