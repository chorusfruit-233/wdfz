# 模块边界与迁移

2026-11-03 双计划实施：学生会检查／请假条／真实楼梯与教室改造，以及 SAN 提示移除／感官反馈已接入。当前变更和验证以[双计划实施记录](validation/双计划实施/README.md)为准；下文历史版本的数量与截图保留当时口径。

核对基线：2026-11-03，基于 main `b88ffb9` 的彻底解耦收口（46 个功能模块、139 份文件契约，其中 121 份有状态私有脚本）；之后成就与积分评级新增 `facts`、`achievements`、`run-record`，本轮增加真实楼梯与感官模块后，清单有 51 个功能模块、166 份文件契约（其中 142 份有状态私有脚本；WebGPU 接入增加设备与 WGSL 后期文件）；手机／巡察机制规则版本为 5，公开速通规则版本为 4，普通存档仍为 `v:1`、`clockVersion:2`。版本号分别属于不同系统，不能互相替代。

本文件描述模块化接口及后续功能的接入。设计背景见[项目解耦与模块化](plan/项目解耦与模块化.md)，验证结果见[测试说明](测试说明.md)。迁移保留本地普通脚本、Three.js、现有玩法与存档格式。PR #25 的天赋规则 2、新局开场 CG、速通、死亡档案室与特殊校园日已随该 PR 合入，接法见[第 7 节](#7-pr-25-功能的接入)。PR #29 的常驻巡察与手机服务器路线见第 8 节。

## 1. 入口与依赖

本地脚本的加载清单是模块清单 `game3d/manifest.js`（PR #26 起：`index.html` 只加载注册表 `game3d/js/modules.js` 和清单，由 `GameModules.boot()` 按清单顺序同步写入普通脚本，`file://` 照样能开；见[模块化与Mod规范](模块化与Mod规范.md)）。纯规则模块在使用者前加载；`app/session.js` 在游戏系统加载完成后组合它们；`main.js` 最后启动。

| 模块 | 责任 | 依赖边界 |
| --- | --- | --- |
| `app/input-context.js` | `GamePolicy`：模式、输入归属、模拟与表现推进策略 | 只接受普通上下文数据，不读取浏览器或全局游戏对象 |
| `input.js` | 原始设备输入、`gameInputContext()`、移动与手势兼容入口 | 把浏览器事件转换成当前上下文中的操作 |
| `app/lifecycle.js` | 可取消资源作用域、失效回调保护、退出钩子与诊断 | `LifecycleCore` 可注入时钟；`Lifecycle` 负责浏览器接线 |
| `app/session.js` | 新局、继续、退出、暂停、恢复与系统清理组合 | 保留 `Game`、`freshState` 名称，避免现有 HTML 和工具调用断开 |
| `domain/player-stats.js` | `StatRules` 纯数值计算与 `PlayerStats` 写入接口 | 不读 DOM、Three.js、存储；通过状态提供函数绑定当前会话 |
| `domain/game-time.js` | 日历分段、运行秒换算与压力插值 | 不执行剧情、音画或存档副作用 |
| `domain/inventory.js` | 背包容量、数量、选中与快捷栏规则 | 数据由实例拥有，物品表现与提示由 `items.js` 适配 |
| `domain/save-data.js` | 校验、规范化、旧时钟迁移与序列化 | 不读当前游戏状态；传入房间、物品索引供校验 |
| `adapters/storage.js` | 可注入存储后端、读写失败结果与诊断 | 不决定何时存档，不删除失败操作前的原值 |
| `systems.js` | 将数值和时间规则接入实际课表、检查、跨日与剧情 | 保留 `settleSan` 等薄兼容入口和现有执行顺序 |
| `save.js` | 字段协议、存储调用和按依赖恢复系统 | `applySave` 恢复规则数据；`restoreSavePresentation` 单独重建界面／表现 |
| `engine/`、`fx/` | 场景、镜头与演出实例 | 临时镜头状态在表现层，死亡预览不写回玩家朝向／位置 |

普通脚本继续是正式交付方式。原生 ES Modules 不作为本轮硬性目标：现有静态托管、离线资源和本地页面兼容优先。没有增加 npm、CDN 或线上构建依赖。

## 2. 状态归属与兼容

| 数据 | 正常运行写入者 | 特殊入口 |
| --- | --- | --- |
| SAN、违规、同化、体力 | `PlayerStats` | 新局种子由 `app/session.js` 初始化；`save.js` 恢复数据，避免重放伤害或奖励 |
| 日历与跨日事件 | `GameTime`／`systems.js` | 新局和存档恢复；调试修改沿用独立设值语义 |
| 背包和快捷栏 | `Inventory`／`items.js` | 新局和存档恢复；保留旧物品函数作为兼容入口 |
| 位置、碰撞与姿态 | 移动、场景交接、驾驶及躲藏系统 | 渲染不再承担卡墙纠正；存档和调试定位仍校验可达位置 |
| 插值视高、视野与行走表现相位 | `VisualState.camera` | `Engine.resetCamera`／`resetSan` 在切换会话时重置 |
| 死亡演出镜头 | 演出实例和 `ANFX.view` | 真实死亡及预览使用独立视图；结束释放表现覆盖 |
| 异象、巡察、路线标志 | 现有异象注册表、巡察系统和路线系统 | 生命周期调用系统自身清理函数；读档字段表负责恢复 |

`S`、`RT`、`AN`、`PAT` 的实现留在其所有者闭包中。旧 HTML、Mod、测试和录像通过同一绑定的全局访问器兼容，不复制状态。游戏文件通过显式端口读取依赖；表现层取得这些状态的只读活视图，嵌套修改会报错。旧异象、巡察等带反馈的控制器属于应用层，不冒充纯规则；迁移新功能时不得把 DOM 或 Three.js 带入 `domain/` 或共享配方。

前一阶段保留的两项耦合已在本轮解除：`ncPressureState()` 查询 `Classmates` 的逻辑场景，堵门和占座不再依赖 `NC.grp`；`GameRandom` 与 `PresentationRandom` 分流，构建模型、画面动画或合成声音不再推进掉落、异象等玩法的随机来源。默认玩法来源仍由浏览器 `Math.random` 适配，但拆流以后不保证与旧版共享随机序列逐次相同；已有存档中已经确定的事件与倒计时照常恢复。

占座布局从已有 `Mechanics.runSeed` 和房间 ID 稳定推导，不再在重建画面时抽取。它不随稍后生成的特殊日种子变化，也无需为模型保存第二份运行状态。

`PlayerStats.changeSan` 默认保留步内尚未裁剪的原行为。原调用有上限或下限时显式传入 `{max:100}` 或 `{min:0}`，最终仍由 `settleSan()` 统一结算死亡。该接口不会自动再次乘天赋或校园压力倍率，避免重复修正。违规的请假／晚间豁免与检查例外仍由规则入口明确处理。

## 3. 输入与时间

`GamePolicy` 读取快照，不保留第二份游戏模式。`mode()`、`inputOwner()`、`simulationAllowed()` 与 `presentationAllowed()` 对同一上下文作出一致判定。

| 上下文 | 世界模拟 | 玩家移动 | 处理原则 |
| --- | --- | --- | --- |
| 正常游玩 | 继续 | 允许 | 课表和威胁按固定步更新 |
| 文字前情／正式过场 | 停止 | 禁止 | 正式过场优先消费跳过键，文字前情只处理自己的翻页 |
| 暂停、普通面板、电脑小游戏 | 停止 | 禁止 | 对话／画面按各自表现策略运行，小游戏有独立更新入口 |
| 手机、新服务器终端、课堂互动 | 继续 | 禁止 | 终端独占文本输入，仍能立即退出；原贪吃蛇保持暂停 |
| 调试打开、未冻结 | 继续 | 面板外允许 | 面板自己的输入被消费，拖动和冻结另外处理 |
| 调试主动冻结 | 停止 | 禁止 | 可保留显式的表现预览 |
| 输入调试密码（页内数字键盘 `DevLock`） | 停止 | 禁止 | 按调试冻结处理（`DEV.locking`）；数字、退格、回车、Esc／F2 由键盘自己消费，其余按键不进游戏；取消后恢复原来的鼠标环视 |
| 异常电梯空间 | 继续 | 按原规则 | `R.noClock` 只停止校历，设备与服务器仍推进 |
| 死亡／返回菜单 | 停止正常模拟 | 禁止 | 只允许对应流程的操作与结束处理 |

模拟运行秒、日历和表现时间各司其职。PR #29 新增 `Mechanics.activePlaySeconds`：只累计已接受的模拟步；后台停止，并在可见性变化时清空累计步长，恢复后不补离线收益。普通卡顿仍遵守主循环步进上限。RTA 独立使用真实经过时间，暂停和后台照计，不能复用设备时钟；接法见第 7 节。

## 4. 生命周期接入

每个异步操作取得自己的作用域。`timeout` 在退出时取消；`guard` 在回调执行前检查该作用域是否仍有效。场景转场和会话更换会使旧回调失效，避免上一局的淡入、字幕、死亡或加载结果覆盖新局。

系统清理在应用组合层注册，清理实现仍属于系统自身。不要在退出入口直接抄写另一个系统的内部字段。反复清理需要安全；局部特效只能释放自己拥有的资源，不得销毁全局共享纹理和模型缓存。

调试诊断可读取输入当前归属、模拟是否推进及生命周期作用域。关键清理失败记录模块和会话信息，便于区分状态残留与视觉降级。

## 5. 存档协议

保留 `v:1`、`clockVersion:2` 和原存档键。`SaveData.prepare` 返回独立副本，旧时钟与冷却只迁移一次；已知字段被校验，未知扩展字段保留。加载错误发生在重置当前会话之前；存储写入失败不先删除旧存档。

恢复依次经过数据校验、会话准备、规则字段恢复、表现恢复和场景进入。保存数据不含 DOM、渲染对象、定时器句柄或函数；读档不重新执行物品使用和奖励命令。

```bash
python tools/check_modules.py
PYTHONPATH=tests python -m unittest test_module_boundaries test_domain_rules test_input_policy test_save_boundary test_lifecycle -v
PYTHONPATH=tests python -m unittest discover -s tests -v
```

`tools/check_modules.py` 还运行 AST 词法链接／契约校验、别名写入检查、表现状态保护、独立随机流约束和碰撞内容校验。`.github/workflows/module-boundaries.yml` 在 push／PR 时运行这些检查及无需浏览器的规则测试。静态约束不替代浏览器回归，也不把应用层间的显式查询和回调宣称为无环。新增纯模块自动接受相同约束；新增文件先登记清单，再运行 `node tools/link_modules.cjs --write`。

测试应重点覆盖真实交叉流程和数据兼容。无浏览器测试验证规则；浏览器验证输入、画质、存档和演出；软件 WebGL 与触屏仿真不代替真实设备性能和真人手感验收。

## 8. PR #29 常驻巡察与手机网络的接入

`domain/phone-energy.js` 负责电量、任务供电时长、每 15 个破解运行秒的发报事件及边界切分；`domain/campus-terminal.js` 负责游戏内虚拟文件与命令；`domain/route-graph.js` 负责图算法。它们不依赖 DOM、Three.js、浏览器存储或宿主命令执行。全校路线由生成工具用精确匹配求解，运行时读取版本化产物。

`PatrolWorld` 拥有唯一敌人的位置和策略，`PatrolNav` 使用从真实碰撞体生成的静态导航数据。`patrol.js` 保留旧调用入口、模型与储物柜交互；换场景只清模型，不销毁权威实体。渲染缓存、当前画质和玩家房间不能决定离屏可达性。`PhoneNetwork.tick` 收到发报事件时调用 `PatrolWorld.revealWireless()` 采样一份静态位置；`PAT.wirelessSignal` 与真实目击 `lastSeen` 分开，后续未目击移动不会改写快照，读取后不补发。新局和数据恢复的纯状态重置不写红屏等表现状态，表现恢复仍由既有入口执行。移除可选迷宫模块时，导航从原白色空间的纯地图生成墙体栅格，永久追踪与读档不引用已缺失的迷宫接口。

2026-11-03：`PatrolWorld` 按 `speed × dt` 消耗路径，穿门不再依赖一次跳过整个门洞的预算；`PatrolNav.segment` 校验非栅格起点的连接，避免读档或重规划时切墙角。只有室外远离玩家的普通巡逻可长瞬移，步行不续期抓捕保护。`content/patrol-zones.js` 是行政楼与网络中心报警区的共同数据源，规则查询、观察点、存档 ID 校验和贴地黄线都使用它；入口告示只负责表现，不读写 `PAT`。区域队列只有区域、序号和时间，与无线静态坐标快照分开。存档格式保持兼容，机制规则升至 4、速通规则升至 3，旧成绩保留但不充当新规则最佳。

`Mechanics.begin(dt)` 在驾驶、电梯等提前返回之前调用一次；随后推进校历、巡察与原系统，`finally` 中的 `Mechanics.finish(dt)` 在危险／救回结算后执行停机仲裁。纯校历跳时不生成运行秒，课堂整理的完整模拟步会推进。不得在各分支再补调用一次设备计时。

`PhoneNetwork` 拥有设备与临时接线；`TerminalUI` 独立于原小游戏的 `PC.on`。终端使用文本输出，键盘事件不进入移动键状态；`visualViewport` 的尺寸和偏移决定软键盘出现时的可见窗口。关闭、断电、转场或强制事件保留输入和工作文件，但清理临时连接。手机和行政楼门禁机共同调用 `WhitelistSync.commit`，只有一份 `RT.data`。

新增存档域为 `mechanics`、`patrolWorld`、`attendanceDuty`、`phoneDevice`、`terminalPuzzle`、`termination`，通过 `GameModules.persistent` 注册。正常读档保留业务进度、断开界面和电脑连接；药丸／免疫保留新路线并解除永久追踪；预知梦重置新路线和检查责任、保留旧白名单与科技党代价。坏谜题只重置谜题域，缺失的新设备域按空电修复，不反复赠送满电；停用 Mod 的数据仍归原命名空间保存。

`cyber` 的 3D 结尾使用 `Engine` 舞台和 `Lifecycle` 作用域，广播声音、模型、纹理随演出收尾或跳过释放，不写玩家位置／朝向。2026-11-03 重做后：天色用只影响表现的 `VisualState.stageHour`（`hourNow()` 优先读它，演出收尾置回 `null`，不动 `S.tsec`）；三处室内布景的明暗由 `lightState` 钩子给出，不加实时点光源（灯光数目一变，所有受光材质都要重编着色器）；文字屏的画布贴图标 `disposeMap`，清场时一起释放。该阶段公开速通规则升至版本 2；后续巡察步行与区域报警升至版本 3，旧记录继续按版本隔离。详细恢复矩阵与验收范围见[对应计划](plan/巡察者常驻、手机网络系统与网安仙人.md)。

## 9. 彻底解耦后的应用边界（2026-11-03）

| 边界 | 负责模块 | 约束与验证 |
| --- | --- | --- |
| 文件依赖 | `modules.js`、`module-contracts.js`、`tools/link_modules.cjs` | 真实词法作用域生成依赖；启动核对已启用模块的提供者，兼容可选模块整块移除；未知名字或重复所有者使检查失败。 |
| 固定步编排 | `app/simulation.js`、`domain/step-pipeline.js` | 命名步骤保留时钟、巡察、危险、恢复、停机仲裁的顺序；驾驶、电梯、死亡提前结束仍恰好收尾一次。可脱离浏览器测试步骤的停止／异常。 |
| 每帧表现 | `app/presentation-loop.js`、`ui/hud.js` | HUD、动画、音频与模型重建不推进世界模拟；同学动作和逃课字迹按输入策略决定是否播放。显示电梯与检查信息不创建持久状态。 |
| 空间数据 | `app/space-layout.js`、`domain/spatial-kit.js`、`content/*-recipe.js` | 相同摆放配方分别交给解析碰撞接收器与渲染 Kit。固定代理预先随仓库交付，不加载顶点、纹理或 GPU 也能得到占地；模型只使用自己的草稿。 |
| 同学 | `domain/classmates.js`、`app/classmates.js`、`fx/classroom.js` | 逻辑拥有占座、堵门、注视条件；画面拥有网格、材质和插值。清空模型不能移除座位、打开被堵住的门或取消 SAN 压力。 |
| 驾驶 | `domain/car-chase.js`、`car-chase.js`、`fx/car-chase-view.js` | 纯规则计算车速、距离、碰撞和路口结果；应用层处理死亡／保护／存档／结局；仪表盘、镜头、追兵提示音维护表现状态。 |
| 检查 | `inspection.js`、`fx/inspection-fx.js` | 检查队列、处罚和 0.8 秒消散间隔由逻辑持有；模型可以缺席、清除或重建，不影响队列推进。间隔保存在原 `RT.inspection` 内，旧档缺省为无间隔。 |
| 其他共享规则 | `domain/cup-trajectory.js`、`app/anomaly-warning.js`、`app/traces.js` | 水杯物理参数与预警窗口不是特效实现；预警可见查询和痕迹记录不要求特效对象存在。`tracesChanged` 通知痕迹表现，`dayAppearance` 通知校庆装饰。 |
| 外部工具与 Mod | `app/mod-adapter.js`、`tools/asset_viewer.html` | 通用加载器只接收服务回调，不读取游戏表或世界状态；模型查看器按同样契约加载所需子集。旧 API 1.0 及录像调用保留。 |

`domain/` 的纯模块不导入游戏实现，使用输入参数、状态提供函数或可替换随机来源。`content/` 存放网格／尺寸／配色／摆放配方，只依赖数据和构建接收器，不查询 `S`、`RT`、GPU 模型包或调查状态。应用组合根负责把服务接起来；每个文件的端口只列实际使用的名字，不向所有规则传入一个包含全游戏的对象。

### 9.1 修改流程与兼容

```bash
# 编辑脚本、登记清单之后；无 npm 安装步骤
node tools/link_modules.cjs --write
python tools/check_modules.py
# 只有修改模型代理时，先导出共享物理数据，再重新链接
node tools/export_collision_data.cjs --write
node tools/link_modules.cjs --write
# 无需 DOM、浏览器、Three.js 或 GPU 的实际规则与全校碰撞检查
python -m unittest discover -s tests -p test_architecture_core.py -v
```

`GameModules.dependencies()` 提供文件、层次、所有者、导入和只读权限快照；模块状态与错误仍在调试面板可查。允许替换的旧绑定只作用于原所有者；全局兼容入口不是另一个状态仓库。自定义 `R.build` 保留兼容，Mod 房间的物理判定应由 `R.collide`／`R.solid` 显式提供。

保留普通脚本和 `file://` 启动能力；发布产物已在仓库内，不要求用户安装构建器。AST 工具和许可证一起放在 `tools/js/`，只参与开发检查。未引入新游戏玩法、第二引擎、存档版本升级或新增积分／成就系统。自动验证范围及设备限制见[彻底解耦验收](validation/彻底解耦验收.md)。

## WebGPU 与设备恢复

2026-11-04：`Engine.boot()` 在设备与后期准备完成后解决 Promise，`boot` 钩子与正式输入初始化随后执行。`RenderDevice` 拥有设备和实际画布；`Engine.status()` 提供后端、阶段和回退原因，`Engine.metrics()` 统一两种统计结构。`#cv` 保留输入归属，实际渲染使用设备画布。恢复阶段通过普通上下文值 `rendererBusy` 阻止模拟与玩家操作，表现层不写玩家数值或剧情。

WebGPU 使用节点/WGSL 后期，WebGL 使用 GLSL；场景、模型、碰撞及保存格式共用。第三方库可在开发时用锁定 npm 依赖生成，正式游戏仍加载已提交的本地普通脚本，不需要线上构建。接入和兼容边界见[WebGPU 与 WebGL 渲染](WebGPU与WebGL渲染.md)。
