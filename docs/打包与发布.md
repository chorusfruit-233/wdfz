# 打包与发布：单文件 HTML 与安卓版

2026-11-06 按用户「源码打包成一个单文件 HTML，然后同样的写一个 APK，不要使用 WebView，原生渲染引擎，发布到 Release」建立（PR #53）。用户选定：APK 内置 **GeckoView**；Release 由 **GitHub Actions** 自动构建发布。

## 单文件 HTML

```
node tools/build_single_html.cjs [输出路径]        # 默认 dist/wdfz-3d.html，约 19 MB
```

- 把 `index.html` 的两份 CSS 内联，`modules.js`、`manifest.js` 内联执行；其余全部脚本（清单里的模块、`game3d/lib` 的 Three.js 与 WebGPU 库、`game3d/mods` 的 DLC、`game3d/assets` 的四档模型包和两档贴图包）作为 `<script type="text/x-wdfz" data-path="…">` 文本块嵌进页面，浏览器不执行这种类型。
- 运行时 `WDFZ_BUNDLE.url(path)` 把路径换成 blob 地址；源码里所有加载点（模块脚本、DLC、模型包、贴图包、WebGPU 库）都经 `GameModules.src(path)`，网页版原样返回路径，单文件版返回 blob 地址。加载顺序、按画质挑包、运行中换画质、`?mod=…`、`?nomod` 都和网页版一样。
- 文本块里的 `</script`、`<!--` 换成 `<\/script`、`<\!--`（JS 里等价）。
- Wiki、效率对比页是另外的页面，单文件里指向线上 `https://wd-fz.github.io/`（环境变量 `WDFZ_BASE_URL` 可改）。
- 存档在浏览器存储里，按页面来源区分：`file://` 打开的单文件版、网页版、安卓版各存各的。
- 验证：`tests/test_single_html.py` 用 `file://` 直接打开（不起服务器），开局、进楼、运行中换画质读另一档模型包、带 DLC 启动，没有页面错误，也没有读零散文件。

## 安卓版（`android/`）

- Java 工程，依赖 `org.mozilla.geckoview:geckoview-arm64-v8a`（Mozilla Gecko 引擎随 APK 打包，自己的 WebGL 与排版），**不用 Android 系统 WebView**。minSdk 26（Android 8.0），只打 64 位 ARM。
- `LocalServer`：只监听 `127.0.0.1` 的小 HTTP 服务，把 `assets/wdfz.html`（构建时由单文件版拷入）交给 GeckoView。固定端口 47831，页面来源每次一样，存档、设置、成就才能留住；端口被占时试后面 9 个（换了端口，存档是另一份）。
- `MainActivity`：全屏沉浸、常亮；默认横屏（`sensorLandscape`，左右两个方向按重力感应转）；页面地址带 `?app=android`（游戏据此隐藏「进入全屏」按钮）；`PermissionDelegate` 允许页面自动播放声音（主菜单一打开就有 BGM）；旋转、键盘等变化不重建 Activity（游戏不重新载入）；切到后台时页面收到隐藏事件（游戏自己暂停）；返回键先发 Esc，1.5 秒内再按一次回到桌面；不是本机页面的链接交给系统浏览器；导入 DLC 文件用系统文件选择器；页面进程崩溃或被杀时重新打开。
- 体积：GeckoView 159 的原生库（`libxul.so` 等）不压缩时 APK 有 217 MB；`packaging.jniLibs.useLegacyPackaging = true` 压缩后约 108 MB（安装时解压到手机上）。单文件页面也随 APK 压缩，本机服务读出来再发。
- 本机服务另有 `GET /__app/orientation?mode=landscape|any`（回 204）：游戏设置「自动横屏」开／关时页面请求它，`MainActivity` 改成 `SENSOR_LANDSCAPE`／`FULL_USER`，并把这个选择记在 App 自己的 `SharedPreferences` 里；启动时（页面载入前）和每次回到前台都按记住的选择重新设一次（PR #56；PR #55 时只靠 Manifest 和页面请求，关掉以后每次启动会先横屏）。Manifest 默认 `sensorLandscape`。
- 签名启动动画（2026-11-06 用户要求「把签名加在门之前，要有签名过程动画，光效等等，科幻感；门那一块等几秒再出现」，PR #55）：`SignatureView`（纯 Canvas 绘制，`res/drawable-nodpi/signature.webp` 由用户提供的签名图去黑底转透明、宽 1400；`signature_glow.webp` 是模糊的光晕层）。运行时按列算出笔画的亮度加权重心与墨色，光笔沿它从左往右写出签名：已写部分带 26dp 软边（`DST_IN` 渐变遮罩）、竖激光扫描线、28 段拖尾、最多 160 颗火花（加法混合）、扫描线背景、四角取景框和 `SIG://DEEPSHAWN · AUTH OK` 代码行；3.7 秒起一道斜光只在笔画上扫过（`SRC_IN`）、光晕亮一下；5.0–5.7 秒故障消散（14 条横条错位、红青通道分离、闪一下）。随后黑场 2.6 秒（门的轮廓透明度 0→0.10→0→0.05→0.16→0→0.06→0 暗闪），再接下面的门。点屏幕：签名／黑场直接到门；门那段页面已画出就直接进游戏。Android 12 起系统启动画面的图标换成透明（`splash_blank.xml`），只是一下黑场。
- 门（PR #54）：`res/drawable/splash_door.xml`（和图标同一扇门）＋ `splash_door_anim.xml`（`res/animator/` 三段：门扇绕门轴转开、门后冷光变宽、变亮，约 1.1 秒）。接着是应用自己的启动层（`activity_main.xml` 的 `splash`，所有版本都有）：同一扇门打开、「里世界」与「武汉大学附属中学」依次渐显上浮、底部细红线跟着页面载入进度（`ProgressDelegate`），游戏页面第一次画出来（`onFirstContentfulPaint`）且门打开已满 1.8 秒以后淡出；整个启动层最多 25 秒保底（PR #55 前是 15 秒）。页面进程崩溃重开时不再出现。PR #55 起门缩到 120dp、进度线离底 24dp，横屏也放得下。
- 签名：`android/app/wdfz-sideload.keystore` 是随仓库公开的侧载证书（不是保密密钥），每次发布用同一把，覆盖安装不用先卸载。要换成自己的证书，构建时设环境变量 `WDFZ_KEYSTORE`、`WDFZ_KEYSTORE_PASSWORD`、`WDFZ_KEY_ALIAS`、`WDFZ_KEY_PASSWORD`。
- 本地构建（需要 Android SDK、JDK 17、Gradle 9 以上；Android Gradle 插件 9.1、compileSdk 37——GeckoView 159 起的要求）：

```
node tools/build_single_html.cjs android/app/src/main/assets/wdfz.html
gradle -p android assembleRelease -PgeckoVersion=<GeckoView 版本>     # 不传时用最新稳定版
```

## Release 工作流（`.github/workflows/release.yml`）

- **PR**（改了 `android/`、打包脚本或工作流）和**手动运行**：只构建，产物在这次运行的 Artifacts 里。
- **推送 `v*` 标签**，或者**手动运行时填版本号**（Actions 页面 release →「Run workflow」，填 `2026.11.6` 这样的版本号；工作流自己建 `v2026.11.6` 标签）：构建单文件 HTML 和 APK，新建 Release 并上传两个文件；手动运行只在工作流已经合进默认分支以后可用（GitHub 的规定）。Claude 的云端容器推不了标签（git 代理只允许推分支），所以由它发布时走手动运行；版本名取标签（去掉 `v`），版本号取运行序号；GeckoView 取 maven.mozilla.org 上当前的稳定版，写在 Release 说明里。
- 开发环境（Claude 的云端容器）没有 Android SDK，`dl.google.com`、`maven.mozilla.org` 也被网络策略拦截，APK 只能在 GitHub 构建机上编：CI 结果就是 APK 的构建验证。

## 没有验证的

- 真机：触屏、性能、WebGL 兼容性、音频、存档在 GeckoView 里能不能长期留住、返回键行为，都要在手机上试。
- 32 位 ARM、x86 手机：没有打包。
