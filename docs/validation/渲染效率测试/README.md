# 渲染效率测试验收

2026-11-05，游戏基线 `4bf8ce1`。独立测试页、设置入口和说明见[渲染效率测试](../../渲染效率测试.md)。引擎和玩法脚本保持基线实现，测试在隔离内存存储的框架里运行。

| 验证 | 结果 |
| --- | --- |
| 专项回归 | 7 项通过，无跳过，原始记录见 `专项.log.gz`。 |
| 纯规则 | 提交／完成／帧调度指标独立；P95 定义；AB／BA 顺序；规格或轮次不足不判优。 |
| 真实后端 | Q0，WebGL 与原生 WebGPU 各跑三个场景的两轮，确认实际后端、固定相机、场景指纹、DPR、分辨率和采样一致；GPU 是真实适配器／设备与 WGSL 渲染。 |
| 高画质 | Q3/Q4 验证实际画质、内部尺寸及采样数。软件设备出现既有设备启动期限内未完成的情况，测试要求如实报告不可用、没有伪造 GPU 行；本项不等于两个高档都完成了本地原生 GPU 采样。 |
| 数据隔离 | 普通存档、设置、成就样例和 sessionStorage 在测试前后完全相同。 |
| 中断与释放 | 手动停止、后台取消、手机布局通过；停止后框架移除，原 WebGL 上下文确认已释放。设备和上下文释放采用异步完成等待。 |
| 静态检查 | 模块入口、启动依赖、纯规则边界和状态归属检查通过；JS 语法及 diff 空白检查通过。 |

测试命令为 `PYTHONPATH=tests python -m unittest -v test_renderer_benchmark`。CI 加入相同专项，只检查正确性，不以耗时、FPS 或固定速度比作为达标线。

保留 `首次高画质验证.log.gz`：最初将软件 GPU 每次高画质启动都成功作为前提，实际设备触发了游戏的启动超时并回退。后续验收区分原生采样与不可用结果；Q0 的原生要求仍然严格保留，没有用回退成绩替代。取消操作也复查了预检与正式采样之间的时序，等待进入采样后再验证上下文释放。

[软件设备流程样例](软件设备流程样例.json)记录一次短采样：流畅档、640×360、三个场景、一轮、预热 0.5 秒、每场景采样 1 秒。它是流程证据，页面会因 GPU 样本不足而拒绝判优。截图在 [pictures/渲染效率测试](../../../pictures/渲染效率测试/)，含桌面和 390×844 手机布局；手机截图是同一结果的排版验证，不是手机硬件性能测量。

本机为 Linux Chromium + SwiftShader 软件设备。数据不能用于断言实体显卡哪个后端更快；实体设备需要使用该页面取得自己的报告。固定画面同步完成测试也不能直接换算为正式游玩的 FPS 增益，具体口径见使用说明。

文件来源指纹和范围见[来源记录](来源.json)。
