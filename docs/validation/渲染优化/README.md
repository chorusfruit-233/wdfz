# 渲染优化验证

基线 main：`25a6b4e`。运行时代码摘要见[来源](来源.json)，原始采样见[results.json](results.json)。

## 改动及工作量

- 室内复用现有的小模型合批：每格不超过 4 个实例、每材质组展开不超过 2,000 顶点；玻璃和污渍保留独立排序，大模型保留实例化。
- 普通清晰画面停止重复生成场景 mipmap。低 SAN、模糊、失焦、扭曲、死亡演出仍更新完整层级；使用 `mipmapsAutoUpdate` 避免每次转换时重建纹理和管线。
- 场景和手持物依靠渲染器自动清屏，移除重复的显式 clear；主菜单截图使用相同规则。
- WebGPU 后期直接输出已经编码的显示颜色，省掉 Three.js 的额外全屏转换及中间 8 位线性颜色量化。离屏诊断仍输出线性值；调用后恢复渲染器状态，保留 WebGL 回退。
- 草地按 32 米分格，每格保留全部实例矩阵和颜色并计算包围球；相机和阴影视锥可以剔除不可见分格。草的总数和形状不变。

同一浏览器、同一教室镜头、流畅档、1000×700 画布，ABBA 顺序，每段预热 3 帧后采 12 帧：

| 工作量 | 基线 | 优化后 |
| --- | ---: | ---: |
| WebGL 绘制调用 / 帧 | 277 | 216 |
| WebGPU 绘制调用 / 帧 | 278 | 216 |
| WebGPU 渲染通道 / 帧（包含 mipmap） | 13 | 2 |
| 场景 mipmap 重建 / 帧 | 1 | 0 |
| 房间 mesh 数 | 215 | 130 |
| 房间存储顶点数（不乘实例数） | 66,617 | 75,313 |

合批以约 13% 的该房间顶点存储增长换取约 22% 的绘制调用减少；总三角形数量不变。这个取值限制小型实例展开，避免大模型复制。

## 计时限制

本地是 Chromium 154 / SwiftShader **软件 GPU**，没有实体显卡。本表为逐帧同步诊断，两个 ABBA 段合计各 24 帧，不能作为玩家设备 FPS 保证：

| 后端 | 渲染调用均值：基线 → 优化 | 含完成等待均值：基线 → 优化 |
| --- | --- | --- |
| WebGL | 4.879 → 3.983 ms | 4.900 → 4.196 ms |
| WebGPU | 4.117 → 4.500 ms | 683.500 → 702.462 ms |

这次软件环境测量中 **WebGPU 耗时没有改善**，不能把通道数减少直接表述为帧率提升；工作量减少是已确认的结果。实体 GPU 的实际收益应使用更新后的 `/benchmark/` 连续模式测量。

测试页默认允许最多两帧在途，记录包含尾部排空的吞吐；不再用逐帧强制同步作为默认性能结论。同步模式保留为诊断，显卡信息改读真实设备 `adapterInfo`。

## 画面与行为

- [WebGL 基线](webgl-q0-baseline.png) / [优化后](webgl-q0-optimized.png)：固定镜头截图逐像素相同。
- [WebGPU 基线](webgpu-q0-baseline.png) / [优化后](webgpu-q0-optimized.png)：去掉中间 8 位线性量化后，暗部色阶更连续；本帧各颜色通道最大变化 7/255。独立灰阶测试与浮点线性参考转换结果相差不超过 1/255。
- 两后端的场景纹理验证重复 clear/mipmap 去除前后像素相同，清空场景后没有前帧残留；模糊激活时恢复 mipmap、结束后停止。
- 合批前三角形数量与合批后相同，ABBA 的碰撞数据 SHA256 相同。草地用例验证实例总数、包围球、独立剔除及分格唯一性。
- 原有 SAN、手持物、颗粒、设备丢失、质量切换、回退行为继续由渲染回归覆盖。

## 复现

```bash
python tools/render_performance.py --output /tmp/render-performance --frames 12 --qualities 0
PYTHONPATH=tests python -m unittest -v test_render_optimization test_renderer_benchmark
python tools/check_modules.py
```

`render_performance.py` 在同一程序中切换回基线清屏、mipmap、合批和输出路径，再按 ABBA 测量。固定房间用于工作量归因，未运行完整剧情。图像和原始帧均保留，不设置硬件 FPS 达标线。

本地记录：前期 15 项专项、14 项架构回归通过；最终输出路径完成后另跑 10 项专项全部通过，无跳过。原始输出保留在本目录的 `.log.gz`；完整渲染检查由 PR CI 在最终提交上运行。
