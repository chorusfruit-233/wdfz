# 建模统计

PR #11（建模重做：Blender 建模 + three.js 运行）收尾时的顶点统计：模型包里每一件模型四档的顶点数、五档画质下全校每个场景实际画的顶点数、10 个固定机位每帧画的三角形和绘制次数，并和 main 对比。只是统计，没有改游戏代码。

- **代码**：游戏代码是本 PR 的 `605ea6d`（Blender 建模、实例化，见 [3D 更新说明](3D更新说明.md#2026-10-29建模全部重做blender-建模--threejs-运行)；这次只加了统计，游戏代码没动）；对比的 main 是 `3d7db17`（程序建模，全部并进大网格）。
- **命令**：`python3 tools/model_stats.py docs/建模统计.json`；main 那份在 main 的检出目录上跑：`WDFZ_ROOT=<main 目录> python3 tools/model_stats.py docs/建模统计_main.json`。原始数据见 [建模统计.json](建模统计.json)、[建模统计_main.json](建模统计_main.json)。
- **口径**：顶点、三角形按实际画出来的算，实例化（InstancedMesh）的按实例个数乘；「缓冲」是顶点和索引缓冲的字节数，几个房间共用的几何体在每个场景里各算一次。「每帧」是渲染器自己的计数：视锥剔除以后、含阴影那几遍（精细及以上有实时阴影）。
- **环境**：无头 Chromium 153 + SwiftShader 软件 WebGL，640×360。数量和显卡无关；建模耗时只能比相对快慢，帧率要在真机上看。教学楼一楼的两个机位有随机入座的同学，几次之间三角形会差几个百分点。

## 五、看到的情况

只记录，这次没有改。

- **顶点和缓冲**：模型细了，实际画的顶点各档都多了（真实档室内 1853 万 → 2611 万）；重复的东西改成实例化以后，缓冲反而少了很多（真实档室内 516.5 MB → 117.0 MB，流畅档 56.5 MB → 20.3 MB），建模也更快。
- **绘制次数**：实例化按「模型 × 材质组 × 24 米一格」分网格，室外一格里常常只有一两个实例（流畅档室外 519 个实例化网格），所以室外机位每帧的绘制次数多了很多：均衡档 55 → 881、57 → 1035 次，流畅档 37 → 409、37 → 472 次。
- **行政楼办公层**：一层 167 套工位和转椅，转椅每把 8,041 个顶点（L0）。真实档一层的实例顶点约 220 万，⑨⑩两个机位每帧 583 万、659 万个三角形（main 184 万、176 万）。
- **流畅档预算**：`test_model` 里流畅档的顶点预算（室内 230 万、室外 27 万）是把每个网格几何体的顶点加起来，实例化网格的几何体只算一份、不乘实例个数，现在量出来室内 79.3 万、室外 26.0 万，测试通过；乘上实例个数，流畅档实际画的是室内 221 万、室外 38.4 万（main 全部并进大网格，两种算法一样：室外 26.3 万）。流畅档室外顶点最多的是 124 台空调外机，L3 每台 566 个顶点。
